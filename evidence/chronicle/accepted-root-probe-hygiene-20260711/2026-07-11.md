# Accepted-Root Temporary-Probe Hygiene Chronicle

## Observation

An untracked diagnostic test can enter an accepted or candidate checkout and
make it dirty while the generic dirty-worktree view does not distinguish that
narrow, explicitly temporary residue from intentional work. In a concurrent
repository, blind cleanup would be worse than the residue: visibility must not
become authority.

## Decision

ETHOS classifies a temporary probe only when Git reports an untracked
`tests/**/test_*.py` file whose bounded header contains `TEMP PROBE`. The
provenance summary retains the exact count and at most sixteen
repository-relative paths. Orientation derives the safe operator choice for
protected roots—remove the probe or migrate it into an owned Work Lane—while
leaving mutation, landing, retirement, and foreign-lane authority unchanged.

## Evidence

- Focused RED tests established that the previous status payload had neither a
  temporary-probe summary nor protected-root remediation.
- Focused GREEN coverage now exercises explicit recognition, negative cases,
  bounded paths, schema presence, protected-root guidance, and ordinary-dirty
  behavior.
- Official OpenSpec strict validation passed for the active carrier. The
  remaining full proof, parity, archive, landing, and accepted-root closeout
  are separate governed steps; this record does not claim their completion or
  hosted verification.

## Boundary

This is a bounded, historical decision record. It does not authorize automatic
deletion, attribution, modification of a protected checkout, interference with
a foreign Work Lane, remote publication, or any claim beyond the classified
reader view.
