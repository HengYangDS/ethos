# ETHOS Native Workflow Runtime And Practice Evolution Evidence

Purpose: record proof and judgment for introducing an ETHOS-native workflow
runtime read model and the governed-passage evolution model that treats Comet,
OpenSpec, Spec Kit, Task Master, BMAD, Superpowers, Agent OS, OpenSPDD,
Shotgun, fspec, and adjacent framework-family inputs as practice carriers.

## Root Judgment

This change does not adopt Comet, OpenSpec, or any adjacent framework as ETHOS
authority. It canonizes the practice model:

```text
question -> boundary -> practice as vessel -> evidence as verification -> commitment as law -> release of the vessel
```

Operationally: `introduce` when no incumbent boundary exists, `compose` when
multiple carriers each contribute bounded value, `refine` when an incumbent
remains valid but needs tightening, `supersede` only when a new practice covers
and replaces an incumbent boundary, `retire` when an incumbent is redundant,
unsafe, wrong, or stale, and `reject` when a candidate remains bounded learning.

The later design refinement made the root passage explicit: ETHOS governs the
movement from question to repository law, bounded refusal, archive, or
retirement. A governed commitment is the minimal auditable handle for that
passage, not a new ontology. Practice claims are evolution carriers for proposed
commitment effects. Candidate sets, experiment protocols, evaluation records,
practice-change records, workflow runtime projections, handoff packages,
task/scenario projections, and method packs are subordinate surfaces that test
or execute that commitment effect. This keeps `上位替代` in its proper place:
supersession is one possible fate, not the default model.

## Governed Commitment Refinement Verification

User review pushed the design one level higher: if ETHOS has no prior mechanism
inside a boundary, the act is introduction; if a mechanism exists and is covered

wrong, unsafe, stale, or misbounded, the act is retirement. The unifying model
is the governed passage; governed commitments are its auditable handles, while
practice claims carry the evidence-backed proposal for how a practice should
affect those commitments.

## Prewrite Admission Repair

During closeout, a malformed prewrite invocation exposed a mutation-admission
defect: a single CLI path token containing a newline was treated as one tracked
candidate path and admitted. This is unsafe because newline-delimited path lists
can be accidentally collapsed into one argument by shell semantics, making the
prewrite report misleading. The defect was repaired at the source by rejecting
path tokens containing ASCII control characters before path resolution or Git
ignore checks.

The repair followed a red-green cycle:

```text
uv run --group dev pytest tests/unit/lanes/hook/test_path_admission.py::test_path_token_control_character_detector_covers_ascii_controls tests/unit/lanes/hook/test_path_admission.py::test_pre_tool_hook_rejects_control_character_path_tokens -q
```

Initial result: failed because the malformed path was admitted. After the fix,
result: `1 passed`. A live repro through `ethos lane prewrite` now returns
`ok=false`, `state=blocked`, and
`required_gaps=["prewrite_path_invalid_control_character"]` for a newline-bearing
path token.

## Final Parity Refresh Protocol

Generic shadow parity evidence is HEAD-sensitive, while the semantic freshness
check is bound to the configured parity-relevant tree. The final closeout uses a
parity-only refresh after all source, docs, schema, claim, and chronicle edits
are committed. This avoids a recursive evidence loop: `evidence/parity/` itself
is not part of the parity-relevant semantic tree, so the last parity-only amend
may advance Git HEAD while preserving `target_semantic_current=true`.

Commands used for the final refresh protocol:

```text
uv run --package ethos ethos parity shadow --adopter generic --target . --execute --write-evidence --json
uv run --package ethos ethos parity gaps --json
```

Required outcome: shadow parity returns `ok=true`, `state=matched`,
`required_gaps=[]`; parity gaps returns `ok=true`, `state=clean`,
`required_gaps=[]`, with `target_semantic_current=true` for the final committed
semantic tree.
