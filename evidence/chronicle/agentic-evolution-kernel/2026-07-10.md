# Agentic Evolution Kernel Refinement

## Judgment

This refinement moves the Agentic Evolution Kernel from a tool-comparison frame
toward a terminal organ model for governed self-evolution.

The root conclusion is that ETHOS should not optimize for maximum autonomous
action. It should optimize for minimum unproven action and maximum proven
learning. External systems may sense, route, schedule, execute, comment, and
propose patches. ETHOS must continue to own type conversion, admission, proof,
claim limitation, chronicle judgment, and upstream guardrail promotion.

The refined organ model is:

```text
Sensor -> Normalizer -> Adjudicator -> Admitter -> Executor -> Prover -> Chronicler -> Upstreamer
```

Each arrow narrows a type:

```text
signal -> intake envelope -> issue candidate -> admitted change -> Work Lane -> proof -> claim -> chronicle -> rule / hook / schema / scaffold / default
```

This is the core anti-collapse rule. The system becomes Dao-aligned only when it
reduces ambiguity, refuses unproven motion, and converts repeated failure into
reviewed structure.

## Implementation Calibration

The previous plan described `ethos intake mine --json` as a proposed future
command. Current repository source now implements it as a read-only E0/E1 read
model. The command returns repository-readmodel output with `repository_truth`
false, empty writes, intake envelopes, issue candidates, and summary flags that
keep automatic raising and dispatch disabled.

This means the next safe slice is no longer read-only mining. The next safe
slice is issue-projection dry run:

```bash
ethos intake raise --dry-run --json
```

That future slice must keep Issue distinct from Change and must keep dispatch
disabled. Its value is not to create more tickets; its value is to prove that
external board projection can remain subordinate to ETHOS authority.

## Framework Calibration

The July 10 review adds sensor-class systems to the earlier managed-agent and
hosted-agent calibration:

- Renovate and Dependabot are supply-chain sensors and candidate patch
  producers.
- CodeQL, SonarQube, and Semgrep are static-analysis sensors and
  evidence-candidate producers.
- Multica, OpenHands, Copilot coding agent, GitLab Duo, SWE-agent, Codex, and
  similar systems remain collaboration, automation, and execution surfaces.

None of these systems should own repository truth. Their findings, pull
requests, merge requests, comments, dashboards, and task completions become ETHOS
input only after normalization, dedupe, admission, proof, and claim binding.

## Boundary

This refinement does not implement issue raising, dispatch planning, agent
assignment, backend execution, result import, landing, publication, or release.
It updates the design truth so later implementation slices aim at the governed
terminal mechanism rather than at a vendor-shaped automation clone.
