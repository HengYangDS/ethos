## Proposed Accepted Resolution Policy

When this Chronicle is accepted, it is the bounded policy input for the native
two-phase resolver:

- `lane_resolution/preserve` applies to the seven exact missing-lease,
  diverged, dirty linked rows selected in the matrix. The resolver must create
  and verify the bundle, tracked patch, untracked archive when present, and
  manifest while retaining the exact branch and worktree for semantic replay.
- `lane_resolution/retire` and `lane_resolution/preserve-retire` remain valid
  exceptional contracts, but the current matrix selects zero rows for either
  disposition. A later effect would require a newly accepted exact decision.
- `lane_resolution/block` records a non-destructive outcome for clean residual
  branches and every valid holder-bound lane. The diverged unbound ref first
  receives a content-addressed Git bundle and then a block record outside the
  linked-worktree resolver. A block is not a completion claim for feature
  intent; it is an explicit preservation boundary.

Never use a raw Git ref move, `git stash`, wildcard cleanup, remote push,
hosted-CI claim, mutation of a valid foreign lease, or deletion of an
unobserved branch under this policy.

The change carries a current matrix and a bounded authorization proposal. It
does not claim that residual patches are semantically absorbed, that holder
work has been handed off, that remote branches or hosted CI have converged, or
that retained recovery packages are clearable. Native resolution receipts and
fresh final status are required for each later outcome.
