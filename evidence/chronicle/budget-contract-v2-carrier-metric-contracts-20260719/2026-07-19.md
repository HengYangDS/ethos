The Git adapter executes one
git ls-files -z -t --stage --cached --others --exclude-standard observation,
cross-checks tag and stage, rejects unsupported tracked modes before worktree
materialization, validates every path ancestor through lstat, catches OSError,
rejects empty inventories, and never returns a clean partial path set. A tracked
regular file deleted from the worktree is intentionally absent under the
declared Git-present semantics.

The carrier matcher accepts only its documented finite canonical dialect. It
rejects unsupported question-mark and character-class syntax, repeated or
adjacent recursive aliases, trailing recursive-star aliases, redundant
exact/recursive-basename pairs, overlapping extension suffixes, and
extension/terminal-suffix duplicate expressions. It does not claim to solve
arbitrary glob equivalence.

CarrierMatch carries explicit path_state = valid|invalid; invalid labels are
digest-suffixed synthetic labels rather than pathname-shape inference.
CarrierInventory uses (relative_path, path_state) as its unique key and
recomputes a digest over full carrier identity, path state, classification
state, matched IDs, and required gaps. Load dataclasses and Pydantic models
reject forged object types, list-valued gaps, empty gaps, duplicate/unstable
gaps, unstable matches, and forged digests.
