# Budget Contract v2 Carrier Resource Boundary Security Pivot

## State

Active authoring carrier on July 21, 2026. This record supersedes the proposed
bounded-only execution decision but does not claim implementation, proof,
archive, land, closeout, publication, or retirement.

## Security Judgment

Independent review rejected the global `bounded_in_process_v1` design. The INI
provider copies every `[DEFAULT]` key into every section before canonical
framing. A 9,590-byte adversarial carrier with 700 defaults and 700 sections
produced a 77.4 MiB Python peak, a 20,489,335-byte canonical stream, and 2.87
seconds of work. A 32 KiB carrier ceiling therefore does not bound the INI
object graph or CPU cost. Catching `MemoryError`, lowering one path, or raising a
ceiling would not satisfy the resource contract.

Only the reader/native bounded GREEN remained uncommitted and was restored from
the Work Lane. The v3 metric-contract and diagnostic-test commits remain on the
Lane as visible migration input and must be superseded by v4. The rejected local
note `/private/tmp/ethos-c1-bounded-in-process-rejected-20260720.md` has SHA-256
`58bf7df020f6b047af131e6ae9ed0ae473c0bff184346f1a6803142cc6500be7`;
its patch has SHA-256
`12db81160513e9a2f6282462d3cbbca319f13d94903041bada9afbd549a25626`.
Both are local-only experiment history, not repository authority or promotion
evidence.

## Superseding Decision

Metric registry and atom wire advance from v3 to v4. Execution becomes a static
provider contract:

- Parser ids `utf8-footprint`, `utf8-control`, and `diagram-contract` retain
  `bounded_in_process_v1` under
  `ethos-source-budget-execution:bounded-in-process-v1`.
- Parser ids `python-tokenize`, `json-stdlib`, `tomllib`, `pyyaml-safe`,
  `configparser`, `jinja2`, and `shell-lexical` use one-carrier/one-process
  `isolated_worker_v1` under
  `ethos-source-budget-execution:isolated-worker-v1`.

Every atom binds the exact `(mode, ceiling, execution-contract id,
execution-contract digest)` tuple. A pure-kernel execution owner mints the digest
from canonical descriptor JSON; provider descriptor v2 separately binds parser,
grammar, normalization, and metric coordinates. No path, role, profile, carrier,
metric, runtime, or caller override is admitted. An isolated failure never
retries in process.

## Worker Boundary

Both modes share descriptor-first parent admission, one `limit + 1` read, and a
direct-byte recheck before parse or spawn. Protocol v1 is length framed,
canonical, path blind, and bounded to a 32 KiB
header, 320 KiB total request, and 64 KiB response/result. Parent and child both
verify content, resolved contracts, provider identity, execution identity, and
ceilings. The parent reconstructs the returned native measurement and accepts
only one typed success or one fixed child gap.

The initial worker resource profile uses CPU soft/hard 5/6 seconds, an 8-second
parent wall deadline, 128 MiB RSS observation at 10 ms, Linux 512 MiB address
space, NOFILE 32, NPROC 1, CORE 0, regular-file FSIZE 0, no stderr, a private
HOME/TMP/cwd, isolated Python flags, closed descriptors, a new session, and
TERM-to-KILL process-group cleanup with bounded reap. Darwin additionally fixes
a 512 MiB virtual-memory growth tripwire above the first successful pre-request
`pti_virtual_size` baseline; the parent writes no request before that baseline.

A July 21 local-only Darwin probe was executed with
`.venv/bin/python -I /private/tmp/ethos_darwin_isolation_probe_20260721.py >
/private/tmp/ethos_darwin_isolation_probe_20260721.json`. The script SHA-256 is
`e127c506e1c854df1d25c9bdbc9565047ffdb12463232ad58c9efe80ffe02582`
and that run's JSON SHA-256 is
`454a7f9d098f51ab0338bd334e33cf9741c6eb07192cebe9453e9164224e7a6e`.
It observed kernel CPU/FD/process/core/file limits, `libproc` telemetry, and
process-group kill/reap; a 48 MiB test watchdog kept the parent alive and removed
the descendant in 12 of 12 memory-growth trials. This is supplied design input,
not acceptance proof for the final 128 MiB RSS/512 MiB VMS profile. Darwin lacks
an independent kernel-hard absolute AS/RSS limit, so the claim remains
resource-fault isolation with telemetry, not a general sandbox or kernel-hard
absolute memory boundary.

## Performance Decision

The local Darwin probe measured a 130.5 ms median isolated import. A separate
planning count estimates 2,889 all-worker starts versus 873 static-hybrid starts,
a 69.8 percent reduction. These are supplied design inputs, not acceptance
performance evidence; the exact workload and latency must be remeasured at the
implementation HEAD. The count reduction does not leave any complex parser on
the bounded path. Persistence, pooling, batching, and fork brokers remain
forbidden in v1.

## Authority And Stop Conditions

V1 remains authoritative, v2 remains inactive, per-file ELOC remains, and all
carrier ceilings remain fixed. C1 stays open until MetricContract v4, provider
identity, protocol, supervisor, platform backends, reader/native admission,
adversarial evidence, inventory, independent review, and exact-HEAD proof pass.

Any dynamic expansion, path exception, worker fallback, unbounded pipe,
unreaped process tree, forged result acceptance, partial snapshot, weakened YAML
safety, changed v1 allowance/debt/terminal/ELOC rule, premature replay/cutover,
or claim that this is a general sandbox is a stop condition.
