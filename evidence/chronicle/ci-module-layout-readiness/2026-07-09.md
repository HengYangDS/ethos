# CI Module Layout Readiness Evidence — 2026-07-09

## Claim

ETHOS local CI caught and closed an import-layer violation in enterprise
readiness: repository policy code no longer imports domain or adapter modules to
compose the `ethos quality enterprise-readiness` result. The aggregation now
lives in `ethos.domain.readiness.enterprise`, while the CLI remains the public
surface and repository policy remains below domain and adapters.

## Boundary

This evidence supports local CI/module-layout readiness only. It does not claim
remote GitLab availability, hosted CI status, release publication, or cleanup of
foreign Work Lanes. It also does not create a new readiness store: the source of
truth remains code, import-linter policy, OpenSpec, tests, and command output.

## Mechanism

- Move `enterprise_readiness_report` from repository policy into
  `ethos.domain.readiness.enterprise`.
- Update `ethos.surface.cli.boundary.readiness` and unit tests to use the domain
  owner.
- Delete the obsolete repository readiness package instead of retaining a facade.
- Preserve `.config/checks/import-linter/contracts.ini`; no exception or baseline
  relaxation was added.
- Update the accepted quality spec and archived OpenSpec carrier:
  `openspec/changes/archive/2026-07-09-ci-module-layout-readiness`.

## Design Judgment

This is a placement repair, not a new entity. Enterprise readiness is an
aggregate domain judgment over lower facts; placing it in repository policy made
repository code import upward and hid an orchestration role in the wrong layer.
Moving it to domain lets import-linter remain a hard quality floor and preserves
the single command surface.
