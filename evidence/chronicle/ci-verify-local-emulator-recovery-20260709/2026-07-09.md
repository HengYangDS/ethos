# CI Verify Local Emulator Evidence — 2026-07-09

## Claim

ETHOS local provider emulator observation modes produce bounded local evidence
when optional emulator tools are missing, while materializing run modes still
fail closed.

## Boundary

This evidence covers the local emulator wrapper/evidence boundary for GitHub and
GitLab provider projections. It does not claim hosted GitLab or GitHub status,
remote publication, or semantic proof of provider execution.

## Mechanism

- `doctor`, `list`, and `dry-run` are observation modes.
- Observation mode with a missing optional emulator binary records
  `tool_available=false`, `returncode=127`, `ok=true`, and hosted status booleans
  false.
- Materializing run modes keep `tool_required=true` and return 127 when the
  required provider emulator binary is unavailable.
- Architecture tests load `tools/ci/ci_templates.py` by file path, so the CI
  owner script remains a script owner surface rather than becoming product Python
  package truth.

## Verification

Focused architecture tests cover missing-tool observation and materialization
branches, plus wrapper invocation without optional environment flags. The Python
lint owner gate passed. The full Python test owner gate passed with 1518 tests
and 100.00% coverage, including the GitLab wrapper path that failed hosted
`ethos:verify` when `gitlab-ci-local` was absent. After the lane commit changed
the repository semantic digest, generic parity evidence was refreshed for the
lane head and `ethos parity gaps --adopter generic --json` returned zero gaps.

## Design Judgment

This repairs a provider-boundary false negative: hosted CI should not fail a
repository proof because a local optional emulator adapter is absent, but any
attempt to materialize emulator output must remain fail-closed. The change makes
that distinction executable without adding a second truth center.
