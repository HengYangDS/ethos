# Detached Worktree Housekeeping — 2026-07-19

## Motivation

The local ETHOS topology contained clean detached temporary worktrees left by
IDE and agent probes alongside dirty recovery and semantic worktrees. Work Lane
coordination did not make the clean detached cohort visible as a first-class
housekeeping action, while raw directory deletion could not distinguish it from
valuable recovery state.

## Decision

The product command inventories all registered worktrees but selects only clean,
detached, unlocked entries below controlled temporary roots. Dry-run is the
default. Apply requires explicit authorization, recomputes the target, and uses
non-forced Git removal. Branch-bound, dirty, locked, non-temporary, current, or
stale targets remain intact.

## Evidence Boundary

Focused tests and command output prove local classification and removal
semantics. They do not authorize Work Lane ref retirement, dirty-content
discard, remote publication, or hosted-CI claims.

## Local Observation

The implemented dry-run inspected 55 registered worktrees. It found five
detached entries and zero removable entries. Three `/private/tmp` entries and
one project checkout were dirty; the remaining clean detached project checkout
was outside every controlled temporary root. All five remained protected. The
controlled-root projection included the active macOS session temp tree,
`/private/tmp`, and the current Codex home `worktrees` directory.

Focused adapter, CLI, and command-registry verification passed 16 tests. Ruff
format and lint checks passed for every changed Python surface, and strict
OpenSpec lifecycle validation passed before lifecycle closeout.
