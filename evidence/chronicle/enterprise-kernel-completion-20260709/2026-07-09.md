# Enterprise Kernel Completion Closeout

## Claim

ETHOS now carries the remaining enterprise/general-purpose planning requirement
as an executable governance-kernel gate instead of relying only on prose or a
single report payload. The gate proves that ETHOS governs the product repository
and governed repositories through one kernel and one transition command loop,
while profiles and adapters remain the only admissible variation boundary.

## Mechanism

- `ethos quality governance-kernel --json` checks four independent surfaces:
  live `governance_context`, profile isomorphism, first-glance product docs, and
  the generic adoption scaffold.
- The gate requires the shared kernel chain:
  `Authority -> Subject -> Commitment -> Change -> Evidence -> Claim -> Chronicle`.
- The gate requires one transition command plane:
  `ethos status`, `ethos plan`, `ethos prove`, `ethos land`, and
  `ethos publish`; `ethos orient` and `ethos report` remain read-only
  projections.
- Profile differences are bounded to authority binding, profile configuration,
  adapter binding, strictness, and rollout. A second command plane, product
  cloning, profile-driven kernel mutation, or adopter-specific product authority
  is a blocking gap.
- The gate has a reusable owner script,
  `tools/ci/scripts/run-governance-kernel.sh`, and participates in
  `tools/ci/scripts/run-product-boundary.sh`, local CI, `system/tools.toml`,
  OpenSpec quality requirements, command-plane docs, and enterprise-readiness
  layer L4.
