# Evidence Lifecycle Signal Hygiene — 2026-07-11

## Claim

ETHOS now separates durable historical claim support from evidence that asserts
current repository state. The claim reader no longer treats an absent HEAD as a
quiet compatibility case: every active claim declares one explicit freshness
contract.

## Observation

At the start of this change, all 96 active claims were dated and digest-bound,
yet none declared an evidence freshness mode. The resulting
`evidence.head_unbound` advisory was repeated 96 times. Historical comparison
against each claim's Chronicle anchor found only two promotion scopes unchanged;
therefore bulk insertion of the current HEAD would have been false evidence.

## Mechanism

- `historical` records durable dated support and makes no currentness assertion.
- `head_bound` requires equality with the current Git HEAD.
- `semantic_scope` records a declared HEAD and digest of non-historical
  promotion targets; a changed target blocks the claim.
- Missing or invalid freshness is a required claim gap. There is no implicit
  legacy mode, ratchet, waiver, or second claim store.

## Boundary

This change classifies evidence honestly; it does not retroactively rerun every
historical delivery, claim hosted verification, modify foreign Work Lanes, or
publish remotely. Present repository behavior remains subject to current source,
tests, schemas, and executed proof.
