## Isolated Pilot Observation

An isolated local clone of an external Git repository was used. Its source
checkout and the pilot's primary checkout remained at the fixed source revision
and clean; neither was modified.

- Strict GitLab adoption identified 16 differing scaffold surfaces and refused
  the apply.
- Explicit overlay planning had no required gap, preserved 16 existing
  adopter-owned files, skipped 31 missing children under existing adopter-owned
  documentation and OpenSpec roots, and generated 19 ETHOS-owned binding
  files.
- An authorized overlay apply succeeded in an isolated task checkout. SHA-256
  checks showed that the selected entrypoint, contributor guide, documentation,
  OpenSpec, and GitLab projection files were byte-for-byte unchanged.
- The applied target passed `ethos fleet inspect`,
  `ethos playbooks check --mode v2-strict`, and readiness `ethos prove` with no
  adoption-surface gap.

The target still reports `candidate_branch_missing` because its existing branch
topology has not yet been mapped to the adopter's `.ethos/workspace.toml` and
does not supply the mapped candidate worktree. That is adopter configuration
work, not evidence that overlay may invent a parallel branch train.

The adopter's native task-worktree command was not runnable in the isolated
task checkout because its host environment had not been prepared from the
primary checkout. The pilot used a local Git-worktree fallback solely to create
the isolated task checkout and does not claim completion of the adopter's
native control-plane lifecycle.
