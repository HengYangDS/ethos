# Input-Bound Python Vulnerability Audit Chronicle

## Observation

The audit gate exported a frozen requirements set and then allowed `pip-audit`
to resolve it again.  The resolver created a temporary environment and failed
while upgrading `pip`, `wheel`, and `setuptools`, before the intended
vulnerability audit ran.

## Decision

The exported dependency set is already pinned and complete.  The owner script
therefore uses `--no-deps --disable-pip`: dependency resolution and pip
bootstrap are outside this gate, while the vulnerability-service query and the
existing local evidence envelope remain in scope.

## Evidence

- The failing focused architecture test reproduced the pre-change bootstrap
  path on both accepted and candidate checkouts.
- A single-variable experiment using the same exported input with
  `--no-deps --disable-pip` audited 63 dependencies and found zero known
  vulnerabilities without a pip bootstrap.
- The final focused test, owner-script run, OpenSpec validation, and
  HEAD-bound proof are recorded by this change's closeout checks.

## Boundary

This is local owner-gate evidence.  It does not claim OSV coverage,
image/package scanning, hosted CI success, remote publication, or that
`pip-audit` reads `uv.lock` directly.
