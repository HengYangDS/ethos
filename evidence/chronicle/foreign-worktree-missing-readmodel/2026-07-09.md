# Foreign Worktree Missing Read Model Evidence — 2026-07-09

## Claim

ETHOS workspace status now fails soft when Git worktree metadata advertises a
foreign Work Lane path or candidate worktree path that no longer exists on disk.
The missing path remains visible as `worktree_binding=missing`; foreign-lane
dirty paths remain empty because no filesystem state is observable; candidate
readiness reports `candidate_worktree_missing`; and accepted-root coordination
stays advisory and observe-only.

The same reader contract keeps candidate branch binding states schema-valid:
`absent` means the configured candidate branch does not exist yet, `unbound`
means the candidate branch exists without a candidate worktree, and `missing`
means Git registry metadata points to a candidate worktree path that disappeared.
Actual worktree list entries remain physical bindings only: `current`, `linked`,
or `missing`.

## Boundary

This evidence supports a reader-view and schema hardening claim only. It does
not authorize cleanup, branch deletion, lease mutation, handoff, remote
publication, or hosted CI claims. The source fact remains Git worktree metadata
plus filesystem reality; ETHOS does not create a new truth store.

## Mechanism

- `worktree_binding(path, current_path=...)` derives `missing` when Git's
  registry path is not the current checkout and does not exist on disk, and
  derives `absent` only from an empty path.
- Candidate read-model schema accepts `absent`, `unbound`, and `missing` because
  candidate readiness may be absent or branch-only during early adoption.
- Actual `worktrees[]` schema remains restricted to physical bindings:
  `current`, `linked`, or `missing`.
- Foreign Work Lane dirty-path inspection skips missing paths and returns an
  empty dirty path set.
- `dirty_provenance` reports unreadable cwd failures as unavailable and dirty at
  the generic dirty-state layer; foreign Work Lane missing paths are explicitly
  downgraded at the status read-model boundary because their binding already
  carries the disorder signal.
- OpenSpec carrier:
  `openspec/changes/archive/2026-07-09-foreign-worktree-missing-readmodel-v2-20260709`.

## Design Judgment

This change reveals small coordination drift without converting it into a
mutation right. It also prevents schema validation from confusing candidate
read-model absence with physical worktree presence. The result preserves the
single kernel: Git registry facts remain the subject substrate; role policy and
binding taxonomy define commitments; tests, schemas, OpenSpec, and command JSON
are evidence; this chronicle and claim bind the result.
