# Foreign Worktree Missing Read Model Evidence — 2026-07-09

## Claim

ETHOS workspace status now fails soft when Git worktree metadata advertises a
foreign Work Lane path or candidate worktree path that no longer exists on disk.
The missing path remains visible as `worktree_binding=missing`; foreign-lane
dirty paths remain empty because no filesystem state is observable; candidate
readiness reports `candidate_worktree_missing`; and accepted-root coordination
stays advisory and observe-only.

## Boundary

This evidence supports a reader-view and schema hardening claim only. It does
not authorize cleanup, branch deletion, lease mutation, handoff, remote
publication, or hosted CI claims. The source fact remains Git worktree metadata
plus filesystem reality; ETHOS does not create a new truth store.

## Mechanism

- `worktree_binding(path, current_path=...)` derives `missing` when Git's
  registry path is not the current checkout and does not exist on disk.
- Foreign Work Lane dirty-path inspection skips missing paths and returns an
  empty dirty path set.
- `dirty_provenance` now reports unreadable cwd failures as unavailable and
  dirty at the generic dirty-state layer; foreign Work Lane missing paths are
  explicitly downgraded at the status read-model boundary because their binding
  already carries the disorder signal.
- `workspace-status.schema.json` admits `missing` for worktree bindings.
- OpenSpec carrier:
  `openspec/changes/archive/2026-07-09-foreign-worktree-missing-readmodel-v2-20260709`.
