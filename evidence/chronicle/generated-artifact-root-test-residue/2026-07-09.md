# Generated Artifact Root Test Residue Chronicle

## Claim

ETHOS keeps repository root denied for generated artifacts while preventing
ignored, untracked coverage/pytest residue from making generated-artifacts proof
verdicts depend on test-gate cleanup order.

## Trigger signal

A live repro showed `ethos quality generated-artifacts --json` and selected
`ethos prove --execute --gate generated-artifacts --gate unit-architecture` both
failed when an ignored root `.coverage` file existed, even though the Python test
owner script later cleaned the same residue.

## Net gain

- Root generated output remains denied by default.
- Only ignored and untracked root `.coverage*`, `coverage.xml`, and `junit.xml`
  are classified as local test residue.
- Tracked root coverage residue and unrelated output such as `proof.json` still
  fail the topology audit.
- Standalone quality and proof now share the same verdict boundary.
