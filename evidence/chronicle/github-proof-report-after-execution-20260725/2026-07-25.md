# GitHub Proof Report-After-Execution Chronicle

## Observation

On July 25, 2026, GitHub dev ETHOS CI run `30172606031` evaluated exact commit
`b2e474590234622fde1631a4ddb514fef6386a9f`. The quality-gates job passed. The
repository-proof job executed the intended single HEAD-bound full proof and
failed only when the compact readiness receipt combined its inputs.

The retained proof is `ok=true`, state `proven`, bound to the expected HEAD, and
contains all 21 gates with evidence digest
`926921043d7364cbbdbfc6c6f54b9c94fc80e77aaa98c30c3521c920520617f2`. Its JUnit
artifact records 3,558 tests with zero failures, errors, or skips. The retained
report is `ok=false`, state `gapped`, with
`coverage_artifact_missing:build/evidence/quality/tests/coverage/coverage.xml`
and proof readiness `proof_not_proven`.

The source order explains both facts: audit and report ran before proof. The clean
runner had no earlier coverage or proof receipt when report executed. Proof then
generated those artifacts successfully, but the script did not regenerate the
report before combining the receipt.

The preceding single-proof change remains correct. Its removal of GitHub's
redundant standalone test step exposed that the pre-proof report had been
accidentally consuming coverage from the duplicate step.

## Decision

Keep the single full proof and reorder only the readiness producer pipeline to
`audit -> prove -> report -> combine`. Add a behavioral regression test that
executes the real script with controlled producer state. Do not restore duplicate
tests, weaken the receipt, rerun the unchanged failed job, change timeouts or
workers, or add retries.

## Network Boundary

change.
