# GitHub Pytest Process-Contention Resilience Chronicle

## Observation

On July 25, 2026, GitHub ETHOS CI run `30155639504` evaluated accepted commit
`626ab408d` on `main`. Quality gates passed, but repository proof failed twice.
Attempt 1 reached 99% before two unrelated lifecycle/report tests each waited
300 seconds in Git subprocess communication. The failed-job rerun reached 99%
before two different source-budget tests failed: one observed `timeout` instead
of `output_exceeded`, and one exceeded its explicit two-second test ceiling.

The changing failure set across identical source rules out those four tests as
one deterministic regression in the Markdown-only commit under evaluation. It
is consistent with process scheduling and temporary-Git contention under four
concurrent xdist workers on the self-hosted macOS runner.

A complete local diagnostic on current accepted commit `8555afde7` used two
workers with the same 300-second signal timeout. All four hosted-failure tests
passed. The run completed 3,556 tests successfully with 100% coverage; its sole
failure was `test_campaign_closeout_reports_local_campaign_packages`, which
correctly reported that this newly created Work Lane did not yet have a tracked
Claim binding. The diagnostic is causal evidence, not a green final proof.

Before implementation, `tools/ci/scripts/run-markdown-lint.sh` also failed on
two accepted MD032 violations in the snapshot replay absorption implementation
plan. Both are missing blank lines between a `**Files:**` label and its following
list. They prevent GitHub quality from reaching repository proof and can be
closed by two blank-line insertions without changing prose.

## Decision

Reduce only GitHub macOS repository proof from four workers to two. Retain the
validated 300-second signal timeout, repository-wide pytest defaults, GitLab's
one-worker projection, the product source-budget worker's eight-second resource
contract, and the no-blind-retry acceptance boundary.

Also add only the two missing list-boundary blank lines reported by the Markdown
owner gate. This is an exact accepted-baseline repair, not a lint-policy or prose
change.

The canonical GitHub template remains the policy owner and the tracked workflow
remains its generated projection. An architecture contract SHALL require the
two-worker value so provider drift fails locally before publication.

## Network Boundary

The workstation is outside the intranet on July 25, 2026. GitLab is not
reachable and SHALL not be probed, pushed, or retried during this change. Its
terminal pipeline and remote-ref state remain unverified. GitHub and local
evidence cannot be promoted into a dual-remote publication claim.
