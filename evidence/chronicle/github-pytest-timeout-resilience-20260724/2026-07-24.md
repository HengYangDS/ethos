# GitHub Pytest Timeout Resilience Chronicle

## Observation

At accepted commit `22e8ad695`, the July 24, 2026 GitHub `dev` and `main`
repository-proof runs lost xdist workers while pytest used the repository-wide
120-second thread timeout. The installed `pytest-timeout` thread handler ends a
timed-out process with `os._exit(1)`, so the controller observed a dead worker
instead of an ordinary test-level timeout failure. GitLab passed the same
accepted commit with its existing single-worker projection.

A read-only diagnostic on the same GitHub runner checkout completed all 2,954
accepted tests with four workers, a 300-second timeout, and signal handling in
286.25 seconds. No worker exited. The slowest individual test took 31.54
seconds in that complete passing replay.

## Decision

The Python test owner script accepts only a paired, validated timeout-seconds
and timeout-method override. Callers that provide neither continue to use the
portable repository default of 120 seconds and thread handling. The canonical
GitHub macOS repository-proof template alone selects 300 seconds and signal
handling while retaining four workers; the generated workflow is byte-identical
to that template. No retry or timeout suppression is introduced.

## Evidence

- RED: the three focused owner-script and provider contracts failed before the
  implementation for the missing validation and projection behavior.
- GREEN: those three contracts passed after implementation.
- The two affected architecture modules passed 45 tests under the owner-script
  Git overlay.
- Strict OpenSpec validation, CI projection consistency, actionlint, shell lint,
  Ruff lint/format, and every ratchet check passed.
- The modified owner script then ran the complete candidate-based inventory with
  four workers and the projected timeout inputs. It reported no worker loss and
  reached 3,437 passing tests; the remaining 10 tests all failed only because
  this active Change did not yet have its tracked claim binding. That run is
  diagnostic evidence, not a green proof, and must be repeated after this claim
  is admitted.
- After this claim was admitted, the same owner-script command completed all
  3,447 tests in 353.96 seconds with 100% coverage, no lost worker, and no
  timeout failure. The slowest individual test took 42.92 seconds.
- Pre-commit review on macOS Bash 3.2 found that `set -u` rejects expansion of
  an empty optional array. A RED functional contract showed the default path
  terminating before pytest invocation; the owner script now appends timeout
  arguments only when the validated pair is present. Functional capture proves
  both the unchanged default argv and the `300`/`signal` override argv.
- After refresh-base moved the signed patch onto accepted/candidate head
  `fe94c0268`, the first exact-HEAD proof passed 18 of 21 gates. Its three
  pytest failures were only assertions that `evidence-freshness` should be
  green; that gate correctly reported the generic parity witness still bound
