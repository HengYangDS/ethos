# GitHub Single HEAD-Bound Proof Chronicle

## Observation

On July 25, 2026, GitHub main ETHOS CI run `30163837735` attempt 2 evaluated
commit `80272b76c22f4fd3964f4d936b4cfa0017a7426a`. Its quality-gates job passed.
The repository-proof job then completed the explicit `Unit and architecture
tests` step successfully before starting `HEAD-bound proof receipt`.

`run-head-bound-proof.sh` invoked `ethos prove --execute --expect-head`, whose
default graph contains the same `unit-architecture` gate. That second execution
ran all 3,557 tests again and recorded three unrelated exact 300-second timeouts
on one xdist worker: two while waiting for Git subprocesses and one while copying
package files. The same commit had already passed the first full suite in that
job, a local 21-gate exact-HEAD proof, and GitHub dev CI.

This is highly consistent with shared-host pressure amplified by duplicate full
execution. It does not convert the failed main run into a pass or establish
absolute causality for each delayed operation.

## Decision

Remove only the direct `run-python-tests.sh` GitHub verify step and retain
`run-head-bound-proof.sh` as the single trust-bearing entrypoint. The nested
proof continues to execute the test gate once with two workers and the existing
300-second signal timeout.

Do not add receipt reuse, a host-global lock, relaxed timeouts, or workflow
retries in this patch. If one full proof still fails under contention, host-level
proof serialization becomes a separate successor with its own authority and
evidence.

## Network Boundary

The workstation remains outside the intranet. GitLab SHALL NOT be probed,
pushed, fetched, retried, or described as current. Its files and hosted state are
outside this change.
