# GitLab Non-root Verify Chronicle

## Observation

At accepted commit `32f66ffedc7bc3515b99a8f8aeb681d769766c3c`,
GitLab pipeline `3219`, job `26847`, ran the `python:3.14` Docker verify job as
UID 0. All 17 failing worker-facing tests returned the stable
`source_budget_worker_isolation_unsupported` gap, and the interrupted inventory
reported 99.95% coverage. The Linux worker backend intentionally rejects real
UID 0 or retained `CAP_SYS_ADMIN`/`CAP_SYS_RESOURCE`, because the declared
`RLIMIT_NPROC` boundary is not enforceable for that identity.

The same GitLab checkout and virtual environment passed representative worker
acceptance contracts after pytest ran as an unprivileged UID/GID. This isolated
the defect to the hosted test-launch identity rather than parser behavior,
dependency resolution, or the accepted source-budget resource policy.

## Decision

Root remains the bootstrap identity. The Python test owner script accepts only
a complete positive-decimal UID/GID pair, requires `setpriv` and a root
launcher, prepares generated build/evidence/temp paths, and then runs only
pytest as UID/GID 65534 with cleared supplementary groups. It unsets the pair
before the child starts so nested owner-script fixtures do not attempt another
privilege transition, then restores root ownership of generated build and
pytest temporary paths before returning to later job stages. GitLab projects
the pair only into `ethos:verify`.

The owner script also preserves exact Git safe-directory entries for the
checkout root and `.git` while appending `core.fsmonitor=false`. The test helper
now removes Git identity overlays without deleting these execution-isolation
entries.

The first full unprivileged replay exposed a second ownership boundary: local
emulator materialization used `git clone --no-local`, whose child
`upload-pack` rejected the root-owned source `.git` even though the caller had
admitted it. The materializer now creates a temporary bundle in the trusted
source process, fetches it into a new repository, applies the tracked binary
diff, and removes the bundle in every outcome.

The next complete replay reached all tests but showed 99.96% coverage because
several Darwin success paths had previously depended on actual Darwin-host
execution. Deterministic contracts now cover libproc symbol binding, valid
group enumeration, non-privileged telemetry, signal forwarding, and settled
permission-denial cleanup on every platform. The exact-ceiling worker
acceptance contract was also corrected: a valid sample may complete with the
full declared vector, while actual memory or recursion exhaustion must return
the stable resource-exhausted gap without partial coordinates.

## Evidence

- RED: three initial owner-script/projection contracts failed before paired
  identity admission existed.
- GREEN: the focused identity, Git-overlay, provider-projection, worker, and
  emulator contracts passed after implementation; the final affected local
  set reported 72 passing tests, and the backend/lifecycle set reported 95.
- A direct Linux reproduction proved caller-side `safe.directory` does not
  propagate into local clone `upload-pack`, while bundle creation and fetch
  succeed as UID/GID 65534 against the same root-owned checkout.
- The final faithful Docker replay used `python:3.14`, root bootstrap, the
  GitLab persistent tool cache, and pytest as UID/GID 65534. It completed all
  3,460 tests in 335.42 seconds with 100.00% statement and branch coverage.
- The replay retained the accepted `32f66ffed` HEAD and applied only this Work
  Lane's tracked patch. It is local provider-faithful evidence, not a hosted
  GitLab success claim.
- The claim was bound to this leased Work Lane; strict OpenSpec validation
  passed the active change and all nine accepted specifications, ETHOS archive
  preflight was clean, and the official archive transition updated the accepted
  quality specification at
  `openspec/changes/archive/2026-07-24-gitlab-nonroot-verify`.

## Boundary

This Chronicle proves the local root-cause diagnosis, implementation contracts,
complete Linux Docker replay of the verify test gate, claim binding, strict
carrier validation, and official archive. It does not yet prove exact-HEAD
ETHOS proof, candidate or accepted advancement, Work Lane retirement, remote
publication, fresh GitHub/GitLab success, immutable record sealing, or
authority over foreign Work Lanes.
