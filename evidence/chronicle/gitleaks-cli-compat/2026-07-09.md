# Gitleaks CLI Compatibility Evidence — 2026-07-09

## Claim

ETHOS local CI secret scanning is compatible with gitleaks 8.30.1 while keeping
the same gate strength. The current tracked-tree scan still uses an isolated
tracked-file mirror, and the Git history scan now invokes `gitleaks git` with the
repository path as its positional argument instead of the removed `--source`
flag.

## Boundary

This evidence supports local owner-script compatibility and secret-scanning gate
execution only. It does not claim hosted CI success, remote publication, or that
another scanner has run. Secret policy remains the root `.gitleaks.toml`; reports
remain local evidence under `build/evidence/quality/secrets/`.

## Mechanism

- Keep `gitleaks detect --source "${scan_root}" --no-git` for current tracked
  source cleanliness.
- Replace `gitleaks git --source "${repo_root}"` with `gitleaks git ...
  "${repo_root}"` for history scanning.
- Add architecture-test coverage that forbids `--source "${repo_root}"` in the
  history scan and requires the positional repository argument.
- Update the accepted quality spec and archived OpenSpec carrier:
  `openspec/changes/archive/2026-07-09-gitleaks-cli-compat`.

## Design Judgment

This is an adapter repair, not a policy relaxation. ETHOS keeps the evidence
boundary and owner script; gitleaks keeps its native CLI. The fix makes the gate
follow provider reality without adding a second scanner, skipping history, or
moving policy into CI projections.
