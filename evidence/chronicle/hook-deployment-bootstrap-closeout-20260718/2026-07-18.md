# Managed-hook deployment bootstrap closeout — 2026-07-18

## Observation

For a candidate that changes `.githooks/reference-transaction`, the accepted
checkout still executes its incumbent shell before an `accepted_ff` dual-ref
transaction can update that tracked file. The incumbent shell can validate
`dev` through the candidate semantic runner, but the release mirror can require
the proposed shell routing before that routing reaches the accepted checkout.
A single atomic mirror transaction can therefore block with both refs unchanged.

## Decision

The closeout adapter compares the immutable accepted and candidate hook blobs.
With an unchanged hook it retains one atomic `dev` + `main` transaction. With a
changed hook it performs two bounded official transactions: an exact-intent,
proof-bound accepted-ref compare-and-swap; accepted-worktree synchronization;
then an exact-intent, proof-bound release-mirror compare-and-swap through the
promoted hook. No raw ref update, hook disablement, or `core.hooksPath` override
is introduced.

## Evidence

The armed regression installs the old `dev` hook at accepted, lands the newer
candidate hook through the ordinary leased Work Lane and candidate path, and
makes accepted-old semantic admission unusable. It proves that local closeout
advances `dev`, synchronizes the accepted checkout, then advances `main` with
the promoted shell. Focused closeout, ref-move, control-replacement, ShellCheck,
Ruff, and Ty checks pass before final HEAD-bound proof.

## Boundary

This record proves only the local deployment-bootstrap mechanism at its tested commit.
It does not prove later candidate landing, external control verification,
accepted closeout, lane retirement, remote publication, remote equality, or
hosted CI.
