# Hosted Observation And Report Closure — 2026-07-16

## Active Decision

Hosted provider observation is runtime-targeted rather than inferred from a Git
remote. A provider without an explicit repository target remains visibly
not_configured and is not executed. Report reads the generated observation as
advisory evidence and keeps local publication, hosted status, repository proof,
and remote publication as separate facts.

## Root Cause

The GitLab remote uses an SSH transport host while glab is authenticated against
an API host with a port, so remote inference rejected the configured repository.
The repository has no GitHub remote, but the installed gh binary converted that
absence into a failed lookup. The envelope then reported state=observed and
ok=true even though neither provider returned facts, and report did not expose
that incompleteness.

## Boundaries

- Provider identifiers remain runtime values; no private repository target is a
  tracked product default.
- Provider observation gaps are report advisories, not repository proof gaps.
- Report local_publication is a scorecard projection only. It does not replace
  ethos publish, probe a remote, or authorize a transition.
- Hosted GitHub status, hosted GitLab status, and remote publication remain
  unclaimed in every observation and report path.

## Remaining Active Work

Materialize local GitHub and GitLab emulator evidence on a committed HEAD, run
an explicit GitLab observation while leaving GitHub unconfigured, then archive
the OpenSpec carrier and execute full HEAD-bound proof.

## Fallback And Kill Signal

Fallback is the previous observation-only envelope without report projection.
Revert this change if an unconfigured provider executes, if report promotes
provider output into required proof, if explicit targets are omitted from
provider commands, or if any hosted/publication claim flag becomes true without
separate promoted evidence.
