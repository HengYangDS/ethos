# Land Proof Readiness Chronicle — 2026-07-09

## Judgment

`ethos land --json` must not report a Work Lane as `ready_to_land` until the
same Work Lane HEAD has a valid executed proof record. Dry-run land remains a
reader view, but its readiness claim is now evidence-grounded.

## Change

- Added a small `proof_readiness_report` read model over the existing
  self-authenticating `executed_proof_record(root, head)` verifier.
- Wired Work Lane land dry-run to evaluate proof readiness only after structural
  land blockers and candidate-base blockers are clear.
- Routed `proof_not_proven` to the exact command:
  `ethos prove --execute --expect-head <HEAD> --json`.
- Kept apply-time proof enforcement unchanged.
- Archived the OpenSpec carrier and fused the accepted `repository-governance`
  spec forward.

## Boundary

This change does not create a new proof store. The visible land payload is a
projection over existing local proof state and current Git HEAD. It does not
claim hosted CI, remote publication, or accepted-root closeout completion.
