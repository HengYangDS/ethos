# Lane Status Coordination Summary Evidence

This evidence binds the `ethos lane status --json` coordination summary
change after OpenSpec archive closeout. The change lifts existing Work Lane
coordination small signals into the command summary while preserving
observe-only foreign-lane authority.

## Evidence Commands

- `uv run --group dev pytest tests/unit/cli/lane_status/test_next_actions.py -q`
- `uv run --group dev ruff check packages/ethos/src/ethos/surface/cli/lane.py tests/unit/cli/lane_status/test_next_actions.py`
- `uv run pytest tests/unit/cli/lane_status/test_next_actions.py tests/unit/coverage/test_cov_repository_edges.py -q`

- `uv run --package ethos ethos parity shadow --adopter generic --target . --execute --write-evidence --json`
- `uv run --package ethos ethos prove --execute --expect-head <head> --json`

## Boundary

The summary fields are reader-view projections over `data.coordination`. They do
not replace workspace-status truth and do not grant write, land, retire, or
cleanup authority over foreign Work Lanes.

## Gate Follow-Up

The first executed proof found two real gate failures: `python-types` and
`unit-architecture`. `python-types` was caused by the new summary helper adding
ty diagnostics, so the helper now normalizes object values before casting.
`unit-architecture` was caused by stale generic parity evidence after the lane
changed command semantics, so `evidence/parity/generic-shadow.json` was refreshed
with an executed generic shadow run.
