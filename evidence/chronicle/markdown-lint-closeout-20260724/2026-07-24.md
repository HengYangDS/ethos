# Markdown Lint Closeout Chronicle

## Observation

At accepted commit `f1e2481ad`, GitHub Actions run `30079628219` failed in
the Markdown lint step. The repository owner script reported one
`MD012/no-multiple-blanks` error at line 61 of
`docs/plans/ownerless-dirty-ancestor-semantic-closeout-20260724.md`.
The same owner script reproduced that single failure locally while the accepted
checkout remained clean.

Git blame binds both adjacent blank lines to commit `236a355a6`, which added
the plan. The failure is therefore an accepted documentation defect, not a
pytest timeout regression and not a GitHub-only runner failure.

change Markdown policy, CI configuration, prose meaning, or any ownerless-lane
decision. Clarify the existing `Documentation Quality Profile` requirement with
the already-enforced owner-script failure scenario. Bind this corrective Work
Lane to a dedicated claim rather than reusing a broader timeout or
lane-resolution claim.
