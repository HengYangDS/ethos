# Module Layout Core Contracts Evidence

## Judgment

ETHOS retired two `ethos-core` suffix-module debts without adding compatibility
facades or package-root re-exports:

- `ethos_core.contracts.branch_roles` moved to the semantic subpackage module
  `ethos_core.contracts.branch.roles`.
- `ethos_core.invalid_states` moved to the semantic state-taxonomy module
  `ethos_core.state.invalid`.

Both old modules were deleted rather than retained as import shims. Callers now
import the concrete defining modules directly, matching the repository rule that
semantic subpackages replace suffix-flat names and that compatibility surfaces do
not become steady state.

## Boundary

This is a module-layout and import-contract hardening change. It does not change
branch role semantics, invalid-state taxonomy semantics, OpenSpec lifecycle
semantics, remote publication state, hosted CI status, or foreign Work Lane
ownership. Historical evidence remains historical; current active promotion
records that referenced the old invalid-state module were updated to the new
semantic path.

## Mechanism

- Add `ethos_core.contracts.branch.roles` and `ethos_core.state.invalid` as
  semantic homes.
- Delete `ethos_core.contracts.branch_roles` and `ethos_core.invalid_states`.
- Update product code, tests, OpenSpec text, and system comments to import or
  reference the new defining modules.
- Shrink `.config/checks/module-layout/policy.toml` from a 9-gap / 8 suffix-module
  baseline to a 7-gap / 6 suffix-module baseline.

## Design Judgment

This intentionally favors a breaking semantic move over compatibility import
residue. The repository already treats package-root barrels, ordinary module
facades, dynamic `__getattr__` forwarding, and `_` alias decoration as layout
violations. Keeping old import paths would preserve the failure mode this lane is
removing.
