# Module Layout Semantic Guard Evidence — 2026-07-08

## Claim

ETHOS now blocks two module-layout drift paths that previously could make a
change look semantically organized while preserving flat or compatibility-shaped
structure: brand-new directories born with too many direct governed modules, and
ordinary modules that use module-level `__getattr__` as a lazy compatibility
export facade.

## Scope

- Extended `rules/module_layout.md` to say brand-new directories cannot be used
  as one-shot flat buckets.
- Extended `rules/module_layout.md` to treat module-level `__getattr__` dynamic
  export shells as compatibility facades.
- Added `module_layout_new_directory_burst:*` findings to the existing flat
  growth policy path.
- Added `module_layout_dynamic_compat_facade:*` findings to the existing facade
  policy path.
- Wired both finding families into `module_layout_report()` so `ethos quality
  module-layout --json`, local CI, proof, report, hosted CI projections, and
  pre-commit projections share the same verdict source.
- Added focused regression tests that first failed before implementation and now
  pass.

## Boundary

This is a mechanism hardening lane. It does not decompose the existing CLI or
clear all historical module-layout ratchet debt. It prevents two additional
normal write paths from adding new layout debt and leaves broader debt reduction
for separately scoped lanes.
