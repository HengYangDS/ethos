## Question

Can ETHOS own clean ownerless Work Lane admission, effect, records, recovery,
and managed family behavior without delegating product authority to an unrelated
host control plane or allowing predecessor records to participate in current
effects?

## Decision

Perform one non-destructive native authority cut:

1. current authority moves to the versioned `lane-resolution-v2` record root;
2. predecessor records remain byte-preserved history and never enter current
   decide/apply/recovery/receipt/clear/inventory behavior;
3. native admission validates the exact decision, Chronicle, configured Work
   Lane role, Git registration/path/HEAD/descriptor registration token, clean
   ownerless state, accepted ancestry, and current reservation classification;
4. an exact pre-fence admission/classification occurs first; when it identifies
   an exact zero-effect retry, ETHOS releases the old exact fence and reservation,
   then acquires a fresh fence and performs the complete under-fence
   re-observation before persisting a new reservation or starting effect;
5. the existing durable reservation, recovery, no-force removal, Git CAS,
   three-state postconditions, immutable receipt, and ordered cleanup remain;
6. receipt, reservation, and clear contracts become explicitly versioned and
   provider neutral;
7. generic coupling governance rejects an undeclared mandatory lifecycle
   executable;
8. the current tracked tree uses neutral historical terminology while Git
   history and predecessor local records remain untouched.
