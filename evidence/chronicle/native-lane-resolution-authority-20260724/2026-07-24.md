## Question

Can ETHOS own clean ownerless Work Lane admission, effect, records, recovery,
and managed family behavior without delegating product authority to an unrelated
host control plane or allowing predecessor records to participate in current
effects?

## Observed baseline

- The accepted root was clean and protected for normal writes.
- The successor Work Lane was created through `ethos lane start` from the current
  candidate head and bound to the current agent lease.
- One pre-carrier point-in-time lane-resolution inventory reported 114 packages,
  9 receipts, 1 clear, 0 inflight, and 0 partial records. Package and receipt
  counts are observational and may change as unrelated lanes close; the cutover
  gate is a fresh zero-inflight, zero-partial, zero-sidecar, zero-fence read.
- The local `closeout_fences` table contained 0 rows.
- No reservation or temporary receipt sidecar was present.
- Current tracked source, contracts, schemas, tests, canonical specification,
  plans, Claim, Chronicle, and archived carrier still contained retired external
  verifier authority and vocabulary.

## Decision

Perform one non-destructive native authority cut:

1. current authority moves to the versioned `lane-resolution-v2` record root;
2. predecessor records remain byte-preserved history and never enter current
   decide/apply/recovery/receipt/clear/inventory behavior;
3. native admission validates the exact decision, Chronicle, configured Work
   Lane role, Git registration/path/HEAD/incarnation, clean ownerless state,
   accepted ancestry, and a fence-held re-observation;
4. the existing fence, durable reservation, recovery, no-force removal, Git CAS,
   three-state postconditions, immutable receipt, and ordered cleanup remain;
5. receipt, reservation, and clear contracts become explicitly versioned and
   provider neutral;
6. generic coupling governance rejects an undeclared mandatory lifecycle
   executable;
7. the current tracked tree uses neutral historical terminology while Git
   history and predecessor local records remain untouched.

## Rejected designs

- archive/freeze/tombstone migration or activation markers;
- moving, copying, deleting, or rewriting predecessor records;
- a dual reader, dual writer, compatibility alias, adapter callback, facade, or
  single-implementation Protocol;
- recreating a host response contract or using a process-table occupancy check;
- hard-coding the default Work Lane prefix or treating a directory name as
  authority.
