# OpenSpec `no-tasks` Scope Bootstrap

## Problem

Official OpenSpec 1.6 reported the newly created
`openspec-no-tasks-bootstrap` carrier as `no-tasks`. ETHOS had excluded that
official active state from lifecycle enumeration, which prevented the
Change-local `scope.toml` bootstrap required for an adopter to start governed
work.

## Bounded Change

The lifecycle adapter now includes `no-tasks` in both default Change selection
and lifecycle enumeration. It remains below `in-progress` and above archiving
or complete records. The pre-existing scope guard remains the sole bootstrap
path: it may admit only the exact untracked, absent `scope.toml` under the one
selected Change; ordinary material paths remain uncovered until that companion
declares coverage.

## Evidence Boundary

Focused RED/GREEN regression ran on this Work Lane after adding the new
selector and scope-bootstrap cases:

```bash
ETHOS_TEST_WORKERS=1 uv run --all-packages --group dev pytest \
  -c .config/checks/pytest/pytest.ini \

```

The committed-head lifecycle, claim, and proof gates remain separate required
evidence. This record does not claim candidate land, accepted-root closeout,
remote publication, hosted CI, or any change to AIGW, Codex, DMX, credentials,
or private session history.
