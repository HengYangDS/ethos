# Owner-unavailable unbound retirement recovery — 2026-07-20

## Fact

The repository has an accepted-ancestor unbound Work Lane whose lease records
an unavailable holder and an absent source worktree. Normal handoff remains
source-holder initiated, and ordinary exceptional retirement remains correctly
blocked for foreign leases. This change adds only a target-specific,
accepted-policy-bound native recovery path.

## Contract

The recovery flag is insufficient by itself. The accepted target Chronicle must
bind the exact active source lease ID, holder, epoch, expected head, absolute
recorded source path, and the source-path-absent fact. A current recovery actor
must be non-empty and differ from that holder. The native lease CAS, mandatory
re-observations, compare-and-delete ref effect, and receipt postconditions stay
unchanged.

## Verification

- Focused exceptional-retirement and CLI regression suite passed with 59 tests.
- Source-owner Ruff checks passed.
- The test cases prove one exact absent-path recovery plus refusal on Chronicle
  lease-tuple drift and source-path reappearance.

## Boundary

This record does not retire an external target, create a generic ownership
takeover, authorize source-holder impersonation, or claim remote/hosted state.
After acceptance, a separate fresh observation must still prove the exact live
target before `ethos lane retire unbound --owner-unavailable-recovery` can have
an effect.
