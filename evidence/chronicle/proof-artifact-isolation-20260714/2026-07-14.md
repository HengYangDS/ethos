# Proof Artifact Isolation Chronicle

## Observation

At `candidate/dev` head `9162d207b69397b890b60f4d25c172da466af0a1`, the
default proof ran `generated-artifacts` before the Python test and Ruff gates.
Observed root `.pytest_cache/` and `.ruff_cache/` therefore caused a topology
failure even though the owner gates are responsible for routing and cleaning
that runtime residue.

On the refreshed Work Lane, the executed proof also exposed two owner-runtime
defects: `ty` discovered an ambient environment rather than the checkout's
semantic venv, and three Python owner scripts required Bash's unavailable
`mapfile` builtin on the macOS-provided Bash 3.2.

## Decision

The product proof graph now adds a terminal dependency from
`generated-artifacts` to its selected `unit-architecture` and `ruff` gates.
The dependency is composed only for the product graph; the shared registry and
adopter graphs remain free of product-owned Python gate dependencies. The test
owner script invokes its denied-runtime cleanup at both entry and EXIT.

The type gate now passes `build/runtime/venv` explicitly to `ty`. The lint,
Ruff-ratchet, and Bandit scripts collect the same tracked-file sets through
Bash 3.2-compatible read loops; no host venv, newer shell, or policy exception
is introduced.

## Boundary

Root caches remain denied. The standalone topology audit stays read-only and
fails closed when residue survives. This is neither an ignore rule nor a
retry/waiver path.

Quality commands remain bound to checkout-local semantic runtime state. The
repair changes no quality threshold, tracked-file scope, or zero-tolerance
policy.

## Evidence

Focused product ordering, adopter graph, and EXIT cleanup regressions passed
before the final verification bundle. Full proof, candidate integration,
accepted-root closeout, lane retirement, and remote publication remain separate
governed transitions.
