# Protected OpenSpec Release Root Gate Evidence

## Claim

ETHOS publish readiness now blocks when the configured release root contains an
active OpenSpec change carrier outside `openspec/changes/archive`, even when the
current accepted root is clean.

## Evidence

- Focused reducer and CLI regression tests:
  `uv run --group dev pytest tests/unit/audit/test_modes.py::test_release_readiness_blocks_active_change_on_non_current_release_root tests/unit/cli/test_contracts_closeout.py::test_publish_dry_run_blocks_release_root_active_openspec_residue -q`
- Live repository probe after the code change:
  `ETHOS_ROOT=$PWD uv run --group dev ethos publish --json`

## Live Probe Result

The current local repository still has `main` carrying
`openspec/changes/ethos-release-hardening`; after this change, publish readiness
returns `ok=false`, `state=blocked`, and the required gap
`openspec_protected_branch_active_change_unarchived:main:release_root:ethos-release-hardening`.
