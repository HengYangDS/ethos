## Claim Boundary

This record covers a local repair to candidate-semantic admission for the two

## Observed Defect

At accepted head `8a1cbb83e93c4417fc569f853d43c55dfdd80943` and candidate head
`0d7749c56c30857ebc373489186e756324ec3378`, a governed dry-run was ready but
the apply path aborted its atomic `dev`/`main` update. The accepted hook chose
the candidate semantic runner only for `dev`; `main` fell back to the incumbent
accepted checkout and rejected the release-mirror transition. Neither protected
ref moved. The apparent `accepted_advanced_concurrently` gap therefore did not
prove a concurrent accepted advance.

## Implemented Boundary

The reference-transaction hook now treats the release branch as protected only
when the local role declaration says `release_mirror = "accepted_ff"`. In that
case the hook resolves the same exact clean candidate runner for both prepared
transitions. Independent release branches and ordinary refs retain their
existing non-protected runner path.

The semantic reducer remains authoritative for exact closeout intent, candidate
head containment, fast-forward, and proof checks. This shell selection change
creates no environment bypass and does not relax raw Git protection.
