# Report Hard Quality Floor — 2026-07-09

## Judgment

`ethos report` must not present a green product scorecard when an existing hard
quality gate would block proof or publication. The report hard quality floor now
aggregates the existing coverage, type, and public-surface docstring read models
alongside size, module layout, product boundary, and contributor policy.

## Boundary

This change does not create a new quality command, policy file, or truth store.
It makes the report scorecard read existing owner surfaces:

- `ethos quality coverage --json`
- `ethos quality types --json`
- `ethos quality docstrings --json`

## Follow-up: coverage writer lock semantics

The first full `tools/ci/scripts/run-python-tests.sh` execution surfaced a
self-referential timing gap: while the owner script had removed stale coverage
XML and was still holding `build/evidence/quality/tests/coverage/.write.lock`,
unit tests that call `ethos report --json` saw the temporarily absent artifact as
a hard coverage failure.

The coverage read model now treats that lock as an in-progress writer signal:
the state is visible, advisory, and non-blocking until the owner writer releases
the lock. This preserves the hard failure for stale or missing coverage evidence
outside an active owner run while avoiding a false required gap during evidence
generation.
