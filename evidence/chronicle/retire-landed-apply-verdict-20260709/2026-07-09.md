# Retire-landed Apply Verdict Evidence — 2026-07-09

## Claim

`ethos lane retire-landed --branch <branch> --expect-head <head> --apply --json`
now preserves the selected lane's retirement outcome in the small JSON summary
even when the detailed `data.lanes` list represents post-apply state and no
longer contains the removed selected Work Lane.

## Root Cause

The CLI summary derived `selected_retire_ready` and `selected_blockers` only by
searching `data.lanes`. That is safe while the adapter returns pre-apply lane
snapshots, but it is brittle for successful apply results: after worktree and
branch deletion, the selected lane can exist only as the operation outcome in
`data.retired`. In that shape, the command can be semantically successful while
the summary makes the selected branch look absent and not retire-ready.

## Scope

- Added a CLI contract test under the semantic `tests/unit/cli/lane/`
sub-package for a successful apply result whose `data.lanes` is a post-apply
remaining-lanes view and whose selected lane is carried in `data.retired`.
- Added a small summary composer for `lane retire-landed` that restores selected
readiness and blockers from `data.retired` when the selected lane has been
removed from `data.lanes`.
- Preserved existing blocked selected-lane and configured lifecycle summary
contracts.
