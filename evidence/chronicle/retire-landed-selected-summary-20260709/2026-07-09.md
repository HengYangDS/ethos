# Retire-landed Selected Summary Evidence — 2026-07-09

## Claim

`ethos lane retire-landed --branch <branch> --json` now reports selected-lane
readiness directly in its summary. A blocked selected branch can no longer be
misread from the global `landed_lane_count`; the summary carries
`selected_retire_ready` and `selected_required_gaps` alongside the selected
branch.

## Root Cause

The adapter already classified lanes correctly: selected unmerged lanes carried
`required_gaps = ["work_lane_not_merged"]` and were blocked. The ambiguity was in
the CLI summary, which exposed only the global count of retire-ready lanes plus
`selected_branch`. When another lane was retire-ready, a blocked selected branch
could show a positive `landed_lane_count` without its own readiness in the small
summary.

## Scope

- Added selected-lane readiness fields to the `lane retire-landed` JSON summary:
  `selected_retire_ready` and `selected_required_gaps`.
- Added a regression test for a selected unmerged lane while another lane is
  retire-ready.
- Updated the configured lifecycle contract test to assert the selected lane is
  ready when retire succeeds.
