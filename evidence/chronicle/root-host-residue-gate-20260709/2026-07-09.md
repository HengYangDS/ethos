# Root Host Residue Gate Evidence — 2026-07-09

## Claim

ETHOS repository hygiene now fails closed when configured host-local residue is
present in the repository root, even if Git status hides it through a global
ignore rule.

## Boundary

This evidence supports the local repository hygiene owner gate only. It does not
claim hosted CI success, remote publication, or automatic cleanup. The gate is
report-only: residue must be removed intentionally, not stashed or promoted.

## Mechanism

- `.config/checks/repository-hygiene/policy.toml` owns repository hygiene knobs.
- `tools/ci/scripts/run-repository-hygiene.sh` executes the policy and scans
  configured root host-residue names before `git ls-files`-based checks.
- Architecture tests cover policy ownership and `.DS_Store` rejection in an
  isolated temporary Git repository, so the negative case does not pollute the
  active Work Lane root.

## Design Judgment

This change follows `几动于微`: a hidden root `.DS_Store` is a small signal of
boundary disorder, not cosmetic noise. The repair does not add a new entity or
command plane. It keeps repository truth, local residue, policy, and provider
projections distinct.
