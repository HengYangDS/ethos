## Question

Can ETHOS complete the required armed-hook proof without a marked request for
its exact current semantic Python recursively waiting on the outer `uv` runtime
lock?

## Observed boundary

The outer proof owner already propagates `ETHOS_RUNTIME_BOOTSTRAPPED=1` and
uses `uv run --no-sync`. The reference-transaction hook still invokes the
runtime wrapper with the current checkout's semantic Python. Before this
carrier, the semantic-Python branch may run `uv sync --check` and fall back to
nested `uv run`; under the outer proof this can deadlock without producing an
executed proof receipt or moving a ref.

## Decision

Use one exact, fail-closed runtime fast path: only a marked request for the
current computed `build/runtime/venv/bin/python` with an executable file and
`pyvenv.cfg` directly executes its original argv. The decision does not depend
on an inherited runtime root because cross-worktree hook execution can inherit
one from its outer owner. Missing, invalid, unmarked, explicit-override, and
non-semantic requests retain their existing paths.

## Claim boundary

This is an implementation authorization only. It does not claim a passed test,
executed proof, archive, candidate land, accepted-root closeout, lane
retirement, local publication, remote publication, hosted execution, or any
change to reference-transaction authority.

## Housekeeping boundary

Housekeeping is limited to task-owned temporary proof output after a successful
proof and governed lifecycle transition. It excludes foreign Work Lanes,
external closeout evidence, prior aborted proof attempts, Git history, SQLite,
virtual environments, and IDE/session state.
