# Runtime-files version manifest boundary

Date: 2026-07-30

## Fact

A valid adopted runtime-files repository can contain `pyproject.toml` without a
Python `[project]` table. The former coupling heuristic treated file presence as
ETHOS product identity and caused `orient`, `report`, and schema validation to
raise `KeyError: 'project'`.

## Evidence

- The focused regression reproduced the original exception before the source
  change.
- The coupling adapter now uses the existing semantic product-root predicate.
- Direct release inspection reads exactly one runtime-files tool declaration
  and its contained version source; malformed metadata yields a structured
  `release_version_manifest_invalid` gap.
- Repository-owned lint and focused release/coupling tests passed before the
  official OpenSpec archive transition. Final exact-HEAD proof, land,
  accepted-root closeout, and publication remain separate gates and are not
  claimed by this Chronicle entry.

## Boundary

This record binds only the local source, test, documentation, and OpenSpec
change that removes the product/adopter metadata leak. It does not claim remote
publication, hosted CI, adopter deployment, or foreign Work Lane authority.
