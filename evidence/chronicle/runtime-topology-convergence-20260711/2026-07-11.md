# Runtime Topology Convergence Chronicle

## Judgment

ETHOS now gives every repository-owned Python producer one semantic runtime
boundary. The source environment is bound to the executing checkout at
`build/runtime/venv`; dependency downloads are a separately declared host or
CI cache concern. A cache therefore accelerates execution without becoming a
source tree, Work Lane lease, evidence carrier, or authority surface.

The runtime bootstrap is the only product-owned adapter for that boundary.
Installed hooks, owner scripts, GitHub and GitLab templates and projections,
and both local provider emulators enter through it or through a deliberately
bounded interpreter override. Product-owned paths no longer fall back to a root
`.venv` or use bare `uv run` as an unbound producer path. The generated-artifact
topology audit enforces this executable invariant while allowing pre-existing
ignored root environments only as non-authoritative migration residue.

The OpenSpec carrier is archived at
`openspec/changes/archive/2026-07-11-runtime-topology-convergence-20260711`;
its one modified requirement and three added requirements are fused into the
live repository-governance specification.

## Local Verification

- The prior implementation HEAD `74d5d8e253095f1c0fdf8a3a90b8f216ed2855b8`
  completed a local, HEAD-bound `ethos prove --execute` record with state
  `proven`, twenty passing gates, and evidence digest
  `31cf6397e0b8b8c57de8c7ae9697aa9f193d7610367c1dcf74cda8503f30fe1a`.
- The provider-projection architecture contract passed: 14 tests verified the
  hosted templates, checked provider projections, and local emulator wrappers
  route Python and uv execution through the bootstrap.
- `ethos quality generated-artifacts --json` is clean: all 58 audited producer
  entrypoints passed and no path or routing gap remains.
- `openspec validate --all --strict --json` passed for all nine live
  specifications after archive.
- A direct, non-owner focused pytest invocation created an ignored root
  `.pytest_cache`; it was recognized as self-created residue and removed from
  this owned lane. Subsequent topology audit was clean. Trust-bearing test
  execution remains the repository owner script, which supplies the declared
  cache home.
- A self-owned candidate landing attempt exposed a distinct nested-bootstrap
  defect: the outer land command held the selected uv cache lock while the
  candidate ref hook attempted to materialize its missing semantic interpreter
  through that same lock. No candidate ref moved. The staged candidate tree was
  recorded locally, the owned process group was terminated after a bounded
  observation window, and the candidate was restored exactly to its original
  HEAD. The bootstrap now places only such cross-worktree recursive
  materialization in a deterministic child namespace beneath the already
  selected cache root; normal invocations and source-environment isolation are
  unchanged.
- Candidate proof then exposed the complementary same-worktree failure: a
  marked owner script was launched beneath a synchronizing outer uv process and
  its own tool invocation waited on the parent's `build/runtime/venv` lock. The
  sampled owned proof process was terminated after a bounded observation window
  without moving any ref. The bootstrap now recognizes only the explicit owner
  handoff marker and adds `--no-sync` to that outer runner; the script retains
  ownership of any required tool synchronization after the parent lock is gone.
- A later interrupted local proof left an empty generated coverage writer lock
  in this owned Work Lane. The current test gate now records the owner process
  identity (PID plus start fingerprint), reclaims only a demonstrably dead
  owner, and reports bounded failure for a live or unknown owner. This preserves
  concurrent evidence-write exclusion without turning a terminated local process
  into an unbounded later wait.

## Boundary

This is local implementation and verification evidence only. It does not
assert hosted GitHub or GitLab execution, remote GitLab publication, global
shared-environment authority, automatic deletion of any existing root virtual
environment, or authority over foreign Work Lanes. Final lane proof, candidate
landing, accepted-root closeout, retirement, and local publish readiness remain
separate governed transitions.
