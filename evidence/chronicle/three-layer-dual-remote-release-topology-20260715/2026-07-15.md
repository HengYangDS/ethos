# Three-Layer Peer-Complete Provider Topology — 2026-07-15

## Decision

ETHOS declares three separate release roles: local verification and installation
remain remote-independent; GitLab and GitHub are peer-complete repository and
CI/CD planes with the same declared repository, CI/CD, update, and distribution
capabilities; GitLab remains the organizational primary publication source.

## Implemented Boundary

The tracked release policy projects both provider planes, their collaboration
surfaces, and the hosted remote-ref boundary. `ethos publish` observes GitLab
and GitHub availability separately, remains read-only, and reports explicit
non-claims. GitHub capability does not establish GitLab primary publication or
GitLab hosted status; GitLab capability does not establish GitHub hosted status.

If the configured `github` remote is absent, its state is `unconfigured`; local
verification remains valid, but the peer GitHub plane is not yet operationally
realized. Hosted CI admits only `dev`, `main`, and `submit/*`; the local
integration ref is explicitly excluded.

## Verification

This Chronicle will bind focused release and publication tests, quality gates,
strict OpenSpec validation, and a HEAD-bound proof from the revised lane head.
Provider observations, candidate landing, accepted-root closeout, remote
publication, and hosted CI remain distinct governed transitions.
