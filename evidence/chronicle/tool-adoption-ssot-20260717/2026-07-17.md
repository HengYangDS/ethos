# Tool Adoption Catalog SSOT — 2026-07-17

## Active Decision

`system/tools.toml` is the sole declaration of quality-tool adoption. Every
entry now declares `active`, `candidate`, `deferred`, or `rejected`; the
quality command projection reads that catalog instead of a parallel static
Python adapter table.

## TDD And Verification Evidence

- The first catalog-projection regression failed because the command returned
  the old static adapter identifiers and the tools schema required only
  `concern` and `tool`.
- The minimal implementation made the catalog payload and state-schema
  regression pass.
- The complete schema-validation file then exposed four adopter-root failures:
  an adopter without `system/tools.toml` attempted to read a nonexistent local
  catalog. The projection now falls back to the installed product catalog only
  when the audited root has no catalog of its own.
- Focused CLI, kernel, and complete schema-validation tests passed 29 tests.
- Configuration lint and focused Ruff checks passed; source-budget accounting
  remained clean.
- The shared quality runtime now supplies both workspace source roots to `ty`,
  eliminating false unresolved-import diagnostics; repository hygiene accepts
  explicit negative stash guidance while still rejecting an imperative stash
  instruction.

## Boundaries

- Catalog projection reports declarations; it does not install, upgrade, run,
  or remove a tool.
- Candidate, deferred, and rejected entries do not become default gates.
- Adopter roots retain an explicitly supplied local catalog when present; the
  product fallback preserves the prior product-schema validation behavior only
  for roots without that contract.
- The type and hygiene repairs are quality-runtime prerequisites, not tool
  adoption-state transitions.
- No provider, remote, release, tag, or branch was mutated.

## Remaining Closeout

Refresh generic parity on the final committed source head, run the required
quality audit and HEAD-bound proof, archive this OpenSpec change, and land the
owned Work Lane through candidate. Accepted closeout and remote synchronization
remain separate governed transitions.

## Fallback And Kill Signal

Fallback is a coordinated revert of catalog states, schemas, and the derived
projection. Revert if tool profiles no longer agree one-to-one with the catalog,
if an undeclared state is accepted, or if an optional/deferred mechanism is
silently treated as an active gate.
