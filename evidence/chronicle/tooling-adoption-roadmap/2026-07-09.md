# Tooling Adoption Roadmap Evidence

Date: 2026-07-09

This chronicle records the planning closeout, selected implementation proof,
and later reference-audit sharpening for the reference adopter and alternate mechanism corpus mechanism
comparison. The roadmap now includes a horizontal reference adopter/alternate mechanism corpus/ETHOS mechanism
matrix that covers provider CI, local emulators, format, lint, architecture, C4,
evidence, runbook, MCP, release, task ledger, Superpowers, Nox, Pixi, Pants, and
domain runtime boundaries. `docs/reference/mechanism-comparison-audit.md` binds
that matrix to a separate evidence-backed reference snapshot so future work can
see what ETHOS has more of, what it has less of, and which mechanisms remain
adapter-only.

This evidence does not claim hosted GitHub status, hosted GitLab status, remote
publication, external signing upload, image-scan completion, or OSV scanner
completion. It binds the roadmap, forge provider contract, OpenSpec
carrier, tool catalog entries, selected active gates, and remaining planned
adapters to an explicit implementation sequence.

## Evidence Boundary

- Local planning evidence only.
- No hosted GitHub status is claimed.
- No hosted GitLab status is claimed.
- No remote publication is claimed.
- Planned tools in `system/tools.toml` are not active gates until their owner
  surfaces and proof coverage land.
- Local provider emulators are projection checks and do not claim hosted
  provider status.
- Domain runtime mechanisms from reference adopter or alternate mechanism corpus are not ETHOS product
  mechanisms unless ETHOS is governing that repository as an adopter.
- External signing upload, image/package scanning, and OSV scanner activation
  are recorded as deferred follow-up Work Lanes, not active gates in this
  change. The `pip-audit` gate is active only for uv-exported resolved
  requirements and does not claim direct `uv.lock` parsing.
