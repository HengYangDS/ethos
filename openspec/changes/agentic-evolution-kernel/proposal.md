# Agentic Evolution Kernel

## Problem

ETHOS has a closed repository governance loop and planned task-ledger / agent
method-pack adapters, but it does not yet have a governed design for turning
external signals, issue trackers, managed-agent platforms, automation canvases,
and coding-agent runtimes into bounded repository evolution.

Without an explicit kernel, external systems such as Multica, OpenHands Agent
Canvas, GitHub Copilot coding agent, Codex, GitLab Duo, OpenHands Resolver,
SWE-agent, or Beads can be misread as lifecycle owners. That would invert the
ETHOS boundary: board state, agent output, task telemetry, or provider PR state
could start to masquerade as repository truth.

## Change

Add a planned product design plan for the Agentic Evolution Kernel. The design
states the ontology, framework calibration, layer ownership, staged evolution
ladder, intake envelope, issue candidate model, dispatch envelope, backend
capability levels, automation permission levels, result package, proof / claim
/ chronicle boundary, and bounded repository evolution rule.

The change is intentionally design-only. It does not implement new intake,
issue-creation, dispatch, backend-execution, or publication commands.

## Capabilities

- `repository-governance`: subject=agentic-evolution-kernel; reuse=extend; change=modify; facet:lifecycle=planning,evolution,dispatch; facet:surface=docs,openspec,evidence,claim; facet:authority=docs,openspec,claim,evidence

## Out Of Scope

- No Multica, OpenHands Agent Canvas, GitHub, GitLab, Codex, Copilot, Duo,
  SWE-agent, Beads, Linear, Jira, or other runtime is made mandatory.
- No external board or agent backend becomes repository truth.
- No automatic mutation, land, accepted-root closeout, remote publication, or
  release is added.
- No new command is implemented in this change.
