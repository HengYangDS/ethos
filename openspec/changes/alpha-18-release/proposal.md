# Proposal

## Why

`v0.2.0-alpha.17` lacks the changes accepted after it:

- Python reference observation follows import bindings, lexical scope and program point, and
  reference admission accepts the executables that a repository's local publication commands
  invoke;
- container and Compose declarations name the runtime values that maintained code reads, and native
  tools no longer report a moved configuration carrier as ambiguous;
- a Change needs one proof instead of two, and a failed proof can return an unlanded archive to its
  exact pre-archive head;
- the hidden pre-push command, the proof execution carrier and five retired policy documents are
  gone, and the policy documents' statements live with their owners.

Adopters install only published releases, and adopter operations that these fixes repair wait for
one.

## What Changes

- `VERSION`, `distributions/npm/package.json`, its `package-lock.json` entry and the three version
  tests move to `0.2.0-alpha.18`.
- The `[Unreleased]` notes become a curated `0.2.0-alpha.18` entry that describes every user-visible
  product change since `v0.2.0-alpha.17`.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. This is release preparation; `skip_specs: true` applies.

## Impact

`VERSION`, `distributions/npm/package.json`, `package-lock.json`, `CHANGELOG.md` and three version
tests change. Product behavior does not change.
