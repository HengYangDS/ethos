## Why

ETHOS already records the compact root philosophy in the product design
contract, but future evolution needs a stronger carrier that treats the poem as
an operational kernel rather than decorative language. Without that carrier,
adapters, assistants, local models, command surfaces, and future frameworks can
be added as tool-centered accretions instead of being absorbed through one
provider-neutral governance root.

## What Changes

- Promote the root philosophy into the ETHOS Tao and kernel model as a canonical
  generative constraint.
- Define how the four lines derive authority, discrimination, visibility, and
  growth boundaries.
- Add an OpenSpec requirement that the core kernel preserves the compact root
  philosophy across docs, contracts, and future projections.
- Add architecture tests so the philosophy remains operational and
  provider-neutral.

- No runtime command behavior changes.
- No provider-specific integration for Codex, Claude, Hermes, local models, IDEs,
