## Why

Official-valid Markdown can silently lose non-goals and open questions in the
ETHOS intent context. The current extractor recognizes one list spelling,
drops unavailable files, and presents partial summaries without their full
source. A structurally valid interpretation can therefore conceal constraints
that a subsequent Agent needs to challenge.

## What Changes

- Preserve each selected official context document, its exact content and
  digest in the transient planning projection; report incomplete observations.
- Replace repeated line-oriented extraction with the existing native CommonMark
  dependency, retaining prose, wrapped lists and real heading boundaries.
- Distinguish source availability and structural compilation from accepted
  interpretation and sufficient behavioral proof.
- Align product responsibility, zero-winner collaboration semantics, the
  existing terminal plan and repository skill with the complete-chain request.

## Capabilities

### Modified Capabilities

- `command-plane`: source-complete, non-authorizing intent context and explicit
  interpretation limits for Agent handoff and planning.

## Impact

The existing OpenSpec intent-context owner, its public governance consumer,
focused tests, product contract, terminal plan and repository skill projection.
The existing markdown-it dependency supplies syntax; no new parser, database,
intent carrier, framework runtime or authoring lane is introduced.

## Out of Scope

- Claiming automated natural-language equivalence or interpreting every source
  constraint through deterministic keyword matching.
- Claiming the complete all-drop execution, recovery, independent-Agent or
  actual-use feedback workload from this source-preservation step alone.
- Rebuilding accepted transaction, quality execution or runtime mechanisms.
