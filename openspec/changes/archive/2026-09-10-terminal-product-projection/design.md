## Context

The canonical product contract covers a usable path from problem and research
through accepted intent, execution, delivery, actual benefit and learning.
The old diagram describes mostly its trust kernel. Hash validation correctly
rejects drift, while normalized export discards attributes needed by consumers.

## Goals / Non-Goals

- Preserve complete product meaning, authority boundaries and target maturity.
- Unblock both renderer implementations through one immutable, checked export.
- Keep required assertions statically readable without imposing drawing geometry.
- Do not claim implementation maturity, renderer acceptance or repository proof
  from successful source export.

## Decisions

The existing product contract remains semantic owner. Retain the existing kernel
nodes and typed effect relations. Add only product distinctions necessary to
represent interpretation, formation, collaboration outcomes and real-use feedback;
these are projected capabilities, not new kernel types or persistent records.

Export normalized identities and provenance together with complete source
attributes and graph-level contracts. Version the changed input shape explicitly.
Keep source digests fail-closed and bind all inputs to the selected commit/tree.
A current-source regression exercises the same export compiler using an isolated
fixture populated from the actual declaration and its selected source bytes.

The view profile selects semantic aggregates and visible copy keys, not hard-coded
rectangles or ports. Required nodes and relations need a declared main-static
copy witness; missing, omitted or hidden-only witnesses fail export. That proves
input obligations, not actual glyph visibility. Renderers must independently
prove painted witnesses, glyph/CTM bounds, stroke and arrowhead envelopes at the
reference viewport. Hidden metadata can trace identity but cannot earn coverage.

Keep readability and overlap constraints hard. Remove arbitrary global text and
character ceilings from hard acceptance; semantic compression is a soft objective
only after required meaning and legibility hold. The visible target notice
prevents design scope being mistaken for shipped capability.

## Migration And Risks

Both renderers must consume the new input shape; no legacy compatibility graph
is retained. Preserve kernel invariants and local proof planes, replacing only
stale meaning and renderer-specific layout. Candidate coordinates can be delivered
before repository acceptance but must be labelled accordingly. Interrupted Python
reference-binding work remains hash-preserved outside tracked intent until this
bounded priority work reaches its safe boundary.

## Post-Source Acceptance Boundary

Exact full proof, governed archive and re-proof, candidate/accepted integration,
installed runtime and required publication readback remain mandatory before
accepted delivery. They are lifecycle effects, not checkboxes whose mutation
would invalidate the exact source snapshot they prove. Renderer import may use
the explicitly labelled candidate; a cross-thread send without acknowledgement
remains unconfirmed. Browser/raster and aesthetic acceptance belong to renderer
verification and are not implied by source export or matching paths.
