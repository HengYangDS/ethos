## Why

The public skill gate embeds a development generation in its identity and keeps
a single-valued strict mode and duplicate compliance report. Current specs still
promise superseded activation migration. Other configuration labels claim
versions no consumer interprets, while the portable gate loader accepts any
integer as its declared format.

## What Changes

- **BREAKING**: expose the existing skill portfolio check as `skills`; consolidate
  its owner into the existing skill package and remove historical command aliases,
  the single mode, duplicate compliance score and per-record contract labels.
- Align current skill specifications with the supported activation schema,
  preserving package, route, composition and invalid-input checks.
- Delete unused configuration version labels and the package-local topology
  declaration version. Keep native supply versions and exact artifact bindings.
- Validate the one supported portable gate declaration version before execution.
- Enforce semantic API visibility across all governed Python consumers: private
  modules and symbols retain their owner boundary; declarations use explicit
  repository selection or interpreter-owned defaults, not ambient discovery.
- Preserve real wire, identity and migration boundaries; record unresolved
  cross-system version distinctions in the existing terminal plan.

## Capabilities

### Modified Capabilities

- `contracts`: stable skill meaning and justified version boundaries.
- `assistant-projections`: one semantic skill portfolio owner and public gate.
- `proof-hosts`: current conformance rather than obsolete migration promises.
- `quality`: necessary declaration versions are enforced; inert labels retire.

## Impact

Existing skill owner, native configuration, gate declaration, canonical product
contract, current specs, docs, rule and skill projections, tests and terminal
architecture source bindings. No new Work Lane, version registry, compatibility
alias, adopter edit or external renderer write. Immutable archives, existing
Attestation hashes, release identities and external protocol versions stay intact.
