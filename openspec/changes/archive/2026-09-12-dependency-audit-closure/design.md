## Boundary And Ownership

The existing vulnerabilities Nox session remains the entrypoint. One dependency
audit module replaces the Python-only implementation; uv and npm own their
advisory interpretation and dependency traversal. ETHOS validates each returned
native report and aggregates pass, block or unknown. CLI/CI consume that owner.
The native audit policy declares required lock inputs and bounded execution.

## Supply Repair

The latest observed direct Markdown tool pins the vulnerable parser exactly.
Prefer upgrading that owner when it releases a corrected dependency; until then,
use npm's scoped override rather than a private parser fork, runtime patch or
suppression. Resolve and verify the stable parser through the native lock owner.
Do not treat this bounded repair as complete latest-stable supply convergence.

## Evidence And Failure Behavior

Capture the accepted source coordinate and hashes of manifests, locks, audit
policy and runner inputs before executing. A failed first ecosystem does not
hide the second result. Local workspace manifests from both native locks also
belong to the input closure. Retain native output, stderr, exit code and timeout facts.
A vulnerability blocks. Missing, malformed or inconsistent output is unknown;
nonzero exit without a finding cannot pass. Input changes invalidate the result.
Online advisory freshness remains distinct from offline correctness and hosted
CI observation. No result authorizes an unrelated effect.

An existing native file lock owns one evidence slot with immediate contention
failure. The owner replaces the old verdict with running/unknown before observing
and stores raw ecosystem output in that same bounded receipt. Interruption leaves
no new green result; a later attempt acquires the released lock and replaces the
incomplete observation. This is process-interruption safety, not a claim of
power-loss atomicity, a result database or complete cache-retention governance.

## Verification

First reproduce the installed parser timeout and native npm advisory at the
public dependency input. Add isolated owner tests for both ecosystem outcomes,
missing lock/policy, malformed and inconsistent counts, command failure/timeout,
input drift and continued diagnostics. Verify the registry places this same gate
before package delivery, not as a prerequisite of offline tests. Re-run native npm audit, the malformed parser case and real
Markdown lint after native supply resolution. Then freeze and use exact full
proof, official archive, accepted/runtime and peer readback.

## Non-Goals

No copied advisory database, permanent security ledger, exception list, second
quality scheduler, blanket tool upgrade or claim of global formal verification.
Restore the authoritative input declaration on rollback; do not hand-edit lock
resolution or silently reuse old audit output.
