## Decision

Keep one strict proof reader and one control-verification owner. An inconsistent
incumbent is an operational recovery problem, not a reason to grow a permanent
reader-negotiation framework. The user explicitly authorizes a bounded local
break-glass with exact coordinates, reason, receipt and post-effect re-entry.
Normal effects and atomic runtime activation remain owned by existing modules.

## Semantic Repairs

A frozen effect is a Mapping, not necessarily a dict. Every proof-execution plan
must pass the same supported-field validation whether its Commitment is present
or absent. New immutable container types must not silently bypass validation.

Control includes executing adapters, runtime selection and Git-effect code.
Control-replacement admission loads the accepted policy from the exact prior
commit. It preserves the stronger prior/proposed verification requirement and
uses the prior declaration on equal strength. Signature trust is not independent
verification; missing or malformed required policy remains a failure.

## Recovery And Simplification

Preserve exact pending bytes before changing the workspace. Reuse accepted
native work-lane refresh to combine independently accepted contributions; old
proofs remain historical after source rebasing. Never overwrite a concurrent
accepted ref or count old proof as evidence for the combined tree.

Remove the uncommitted evaluator-binding module, prepared-runtime wrapper and
hook prepare surface. They have no accepted consumer and introduce a second
migration path. Keep their demonstrated proof/control counterexamples, not their
unused implementation. Prepared runtime generations with no live reference are
reclaimed by the existing generation owner.

If the new exact proof is rejected solely by the old reader, a user-authorized
one-effect recovery may use the verified successor to evaluate that exact effect.
It must retain current policy, source/tree, proof, actor, Lease and expected-old
ref checks; no permanent configuration change or reusable permission is created.
The resulting refs, worktrees, hooks and runtime are reobserved before re-entry.

## Quality And Measurement

The two 50,000 ceilings change only the native numeric declaration. Keep combined
line/branch coverage at least 95%, existing per-file ceilings and truthful
artifact exclusions. SCC diagnostics, semantic references and test evidence are
complementary observations, not additional acceptance authorities. Measure
useful defect sensitivity, maintenance cost and verification latency rather than
tool count or code volume alone.

## Native Credential Recognition

The upstream Sourcegraph rule treats an arbitrary 40-hex string as a credential
when a provider keyword exists anywhere in the scanned fragment. A referenced
Git object is not credential evidence. Override that rule through the existing
native Gitleaks configuration with the provider's prefixed token grammar;
retain the default generic credential rule for legacy unprefixed assignments.
Validate both positive forms and negative source OIDs using the native scanner.
No report suppression, excluded file, reduced scanner coverage or second parser.

## Verification

Reproduce unsupported Facts with and without Commitment; candidate policy
downgrade; and runtime/hook/Git-effect paths escaping control classification.
Run the focused public owners, then static checks and exact full proof after
source freeze. Verify negative admission and a legitimate success path. Restore
or disposition all preserved inputs and retire only observed unused resources.
