## Cause And Boundary

Production validates exact manifest material, observes the copied interpreter's
native prefix and executes the module smoke check before exposing a new runtime.
The small fixture intentionally uses a virtual environment rather than a full
relocatable distribution, but its validator checked only selected manifest bytes.
This let a cold or unusable executable reach the later ten-second hook query.

Keep the fixture's declared reduced boundary, not an invented full distribution.
Inspect its real executable and virtual-environment prefix through the existing
native observer, and execute the real module version command when materialization
requests smoke. The fixture can accept an external base prefix by design; it
cannot accept the wrong executable, wrong runtime prefix or failed module startup.
No observation is memoized and no production timeout is altered.

## Falsification

Wrap the native child calls without replacing them: a correct materialization
must observe the copied executable and execute its requested smoke before return.
A broken fixture module path must fail at materialization rather than later hook
activation. The image retains exclusive inode ownership and source bytes remain
unchanged. Replay the exact post-archive installation failure and affected runtime
consumers with cleanup before another frozen proof.

The hosted verification sibling exposed another fixture startup cost: each
semantic case generated a new executable program. A native trace and six-sample
comparison distinguish that cost from passing data to one immutable executable.
Keep the real shell transport and child process, share only fixture code, and
move variant proof/report material to each isolated repository. Retain the
timeout and every semantic rejection case; timing alone does not prove the
original timeout's entire cause.

The prior status Change remains archived with its true failed post-archive proof.
