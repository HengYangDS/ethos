## Why

Historical commits retain wrong-account or placeholder identities. The public
signature repair only handles an unsigned accepted tip. Public commit-range
admission accepts an invalid signature envelope and lets a candidate weaken its
own signing policy. The separate mutable Git identity switch defaults off.

## What Changes

- Bind subject, declared author/committer identities and native signature
  verification to one compiled commit policy and trusted integration baseline.
- Extend the existing repair owner with exact history selection, byte-preserving
  replacement validation, provenance, CAS and recovery instead of manual bypass.
- Revalidate archived intent, current proof, runtime and independent publications
  after a repair without rewriting historical Attestations.
- Correct the confirmed historical identities using that public capability.
- Qualify this repair against the user-authorized current stable supply, keeping
  lockfiles, package resources and hosted projections bound to the same selection.

## Impact

The existing commit policy, native Git observation/signing, repair effect,
archive provenance and public admission owners implement this boundary. The
existing terminal plan retains execution order; no second roadmap or parser.

## Out Of Scope

No adopter mutations, fabricated original signatures, blanket author rewriting,
key registration, permanent hook bypass, or changes to product content during
historical replacement. Legitimate historical authorship remains intact.
