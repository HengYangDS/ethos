# Global Declarative Compression Program

## Why

ETHOS has strong governance boundaries but its maintained executable source keeps
growing across product Python, tests, tools, reports, configuration, templates,
and provider projections. The existing code-size gate protects individual files;
it cannot prove that a migration removed repository-wide procedure. A new
framework would worsen the problem unless it replaces and deletes the mechanisms
it subsumes.

## What Changes

- Establish a whole-repository source-budget and compression-debt contract.
- Admit executable carriers and tools only with format, syntax, semantic,
  behavior, cache, supply-chain, and owner coverage.
- Replace local CI emulator listing with actual selected formal-job execution.
- Converge declarations, policy predicates, read models, lifecycle transitions,
  and CLI bindings toward typed compilers and pure reducers.
- Use restricted CEL only for predicates over typed facts and retain `graphlib`
  as the common graph kernel.
- Require every migration to delete old production code, tests, scripts,
  declarations, and compatibility residue after parity.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `quality`: subject=global-declarative-compression; reuse=extend;
  change=modify; facet:lifecycle=authoring,validation,runtime,release;
  facet:surface=cli,docs,schema,openspec,ci,package,test;
  facet:authority=source,test,schema,docs,evidence

## Impact

The program affects quality policy, tool declarations, CI projections, package
development dependencies, declaration contracts, policy/read-model compilers,
tests, templates, and documentation. Repository truth and the ETHOS lifecycle
remain owned by ETHOS; external tools are bounded mechanism providers.

## Out Of Scope

- No workflow platform, scheduler, or hosted control plane.
- No OPA/Rego, NetworkX, effect/DI, persistent collection, or configuration
  language runtime in the ETHOS kernel.
- No claim that local emulation is hosted-provider proof.
- No source-budget evasion by moving code to TOML, CEL, Jinja, generated output,
  or uncounted test/tool paths.
