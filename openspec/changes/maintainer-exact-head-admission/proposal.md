## Why

ETHOS can already prove a candidate and apply an exact candidate-to-accepted Git
CAS, but its protected hooks independently re-derive proof and topology.  That
duplication creates a circular admission failure for an already signed,
archived, exact, independently proved head and leaves operators with gap names
or hook bypass instead of one executable governed closeout command.

## What Changes

- Make `ethos land --closeout` the sole public owner of accepted-head admission,
  including exact local proof or a package-only external verification receipt,
  immutable dry-run coordinates, exact Git CAS, post-observation, and
  Attestation.
- Bind external evidence to the exact candidate commit/tree, proof floor,
  policy, implementation, provider identity, validity, and signature without
  allowing that receipt to mint repository authority.
- Make reference-transaction, pre-push, status, and plan consume or project the
  same prepared closeout decision instead of independently reconstructing proof
  or requiring the protected local ref to move before it may be pushed.
- Emit one complete, copyable `ethos ...` next command from every blocked
  closeout state, with current repository coordinates and no placeholders.
- Preserve developer proposal behavior and support a profile-selected local
  proof plane when no Forge exists; absence of Forge never fabricates hosted
  facts.
- Delete duplicate hook-local protected-role admission and placeholder closeout
  remediation as the shared owner lands.

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `adapters`: protected Git hooks consume the prepared exact-head admission
  decision and external verification remains a non-authorizing adapter input.
- `command-plane`: accepted closeout exposes the single executable admission
  path and projects one coordinate-bound next action.
- `repository-governance`: exact candidate identity, proof plane, ref effect,
  post-image, and Attestation form one accepted-head transaction for Forge and
  local-only profiles.

## Impact

- Accepted-root closeout orchestration and exact candidate promotion.
- External verification receipt validation and proof selection.
- Reference-transaction and pre-push admission projections.
- Status/plan/hook remediation payloads and public command documentation.
- Black-box and producer-to-consumer tests for stale, forged, wrong-subject,
  wrong-verifier, local-only, and already-admitted protected-object paths.

Out of scope: AIGW/Proxy source changes, a new role-transition command, a Forge
workflow state machine, supply-chain upgrades, performance work, or a second
proof/authority store.
