## Why

A pending native merge exposes two legitimate Changes, but ETHOS treats visible
directory count as ownership and prescribes refresh or status again. The Git
parents retain the missing distinction: the lane's intent versus the incoming
contribution. The merge must remain recoverable without rewriting either parent.

## What Changes

- Attribute active Change selection from exact base, lane and incoming Git trees.
- Evaluate each selected lifecycle result against its own Change, preserving
  legitimate coexisting intent and blocking unresolved attribution.
- Extend the existing refresh boundary with history-preserving merge preparation,
  exact-state continuation and safe abort, retaining native Git operation state.
- Preserve recovery material before destructive projection and recheck authority,
  runtime, parents, index and working content at the actual effect boundary.
- Project one actionable recovery or an explicit unsupported prerequisite instead
  of an unchanged status loop or a rebase into an existing merge.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `repository-transaction`: native merge attribution, continuation and preservation.

## Impact

OpenSpec selection/lifecycle, native Git operation observation, the existing
refresh owner, commit creation, status/CLI projections and focused governed
fixtures. Existing Lease, commit policy, CAS and Attestation owners remain sole
authorities. No adopter source, merge, index, runtime or Lease is modified.

## Non-Goals

No second Change registry, stored workflow graph, automatic conflict resolution,
force push, fabricated completion, full-repository backup or provider policy.
