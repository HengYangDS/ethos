# Proposal

## Why

DR-0029 makes the copies run a law of every release: before each tag the candidate is moved and
proved on a disposable copy of every governed tree that the releasing host can read, a session
other than the batch's authors reads the result, and the entry prints the count for each gap
code. No command of this product performs it. It ran twice, on two candidates of 0.2.0-beta.11,
on the private scripts of the session that reads it, and the weekly page takes its measure by
hand. That is the class that `supply-currency-verb` names for supply: a law that one
session's scripts execute.

Measured by that session on its two runs, and relayed to the release lead on 2026-11-16:

- The scripts are six files of 417 lines together.
- Their own defects cost three host proofs and one wrong first result: an admission wait of one
  hour inside a deadline of 130 minutes; a clone made without its remote, which one governed
  tree's release test needs; a launch from the harness's shell after the harness had removed
  Mise's activation variables alone, under which one proof failed a test that it passed from
  an empty environment; and a reader that took an absent key for zero, caught before use.
- The second run took 8 hours 40 minutes for ten trees, one proof at a time behind the host
  queue, and its last tree needed three proofs before the candidate's own result could be read.

What the run needs, each solved privately today:

- Install a packaged candidate from its archive and check it against the package's own smoke
  record.
- Make an independent copy of a tree that keeps a remote it can read and cannot write.
- Run the preview commands under the predecessor and under the candidate.
- Apply the candidate's projection to the copy. `ethos lane project --apply` refuses in a copy
  with `root_binding_mismatch`, so the scripts apply a patch.
- Prove each copy under one host ticket, in an environment that no launching shell changed.
- Compare each tree with its result under the predecessor, and count each gap code.

## What Changes

Candidates for a design; none is decided.

- One command of the release performs the run for a named candidate and a set of trees, and its
  result is the table that DR-0029 asks for: each tree with its verdict under the predecessor and
  under the candidate, what is new, and the count for each gap code. The product names no tree;
  the trees are the caller's input or the host's recorded consumers, which
  `release-predecessors` reads.
- The copy is the product's: an independent clone under disposable runtime work, with a remote
  that is read and never written, and removed when its result is read.
- The projection of a copy. To decide: an apply that a copy admits because it is a copy, or the
  projection's patch as a result of the candidate that the run applies. Neither weakens the
  refusal in a governed root.
- The proof's environment. One proof of the second run failed from the harness's shell and
  passed from an empty environment; `gate-environment` holds the cause, a declared command
  gate that receives the launching environment. The command launches each proof from an
  environment that it builds, and copies no repair.
- The result is the record that `second-reader-record` asks for the copies run: its subject, its
  reader and what was not run. The release's tag condition reads that record in place of a file
  that the release lead writes by hand.
- The first regression is the two runs' own records: the same trees, the same counts.

## Impact

The release commands, the host's work directories and the release's tag condition. It adds a
command and no rule: DR-0029 already holds the law. Until it lands, the reading session's scripts
and the release lead's hand-written record perform the run, and both stay outside the repository.
