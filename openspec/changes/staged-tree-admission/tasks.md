# Tasks

## 1. The staged tree decides when it passes

- [ ] 1.1 Judge the index-target preview and the commit by their staged tree. Done when a whole
      landing previewed against a refused base passes, the commit of the same index passes with
      the working files at that base, and both answers name the same tree.
- [ ] 1.2 Keep every other answer. Done when the thirty-seven recorded cases show no pass that
      becomes a non-pass, and the worktree preview and a merge continuation project nothing.
- [ ] 1.3 Report and do not refuse. Done when a staged tree that fails beside whole working
      files, one that cannot be observed and one whose evaluation raises each pass with the gap
      reported, and an unobservable tree is refused once the obligation is armed in the test.
- [ ] 1.4 Commit through the installed hook. Done when Git's own run of `pre-commit` admits the
      staged landing and the commit holds the staged tree.
- [ ] 1.5 Name who refuses a working-file fault that Git cannot stage. Done when each of the
      measured cases names the reader that refuses it after this change, or says that none does.

## 2. The record of the change

- [ ] 2.1 State the change in the changelog. Done when the unreleased section names the staged
      tree's decision, the reporting obligation, the commit that now passes beside a working-file
      fault, and the two refusals that a later release arms.
